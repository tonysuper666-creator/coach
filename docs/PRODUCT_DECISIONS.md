## 逐条决定清单

### 1. 软件开发第一、项目优先级未降
- **决定**：Coach 项目优先级从未降低，保持最高执行优先级不变。
- **目标**：对本项目而言，准备眼前这场考试不是最要紧的，**最要紧的是把可用软件开发出来**，服务长期学习与知识摄入。
- **执行原则**：一切以交付可用、可运行的软件功能为第一导向，不因为局部考试材料或周次未齐备而挂起软件开发。

### 2. 长期读教材/文献/好书、课程可配置
- **决定**：产品定位是服务长期的深度知识摄入，包括读教材、文献和有用的书籍，不把产品写死为某单一门课程。
- **架构支持**：课程与学习内容保持高度可配置（如课程 ID、学习目录、教材与题包均可配置），当前的考试课程只是填充与验证材料。

### 3. 考试资料仅填充，不因缺课件/真题挡功能
- **决定**：眼前考试的资料仅作为目前最好的真实填充与闭环验证材料。
- **执行边界**：缺某一周的课件、课后题或真题，绝不能作为阻挡软件功能实现的理由。软件代码、架构与通用功能（阅读器、做题流、复习队列、掌握度账本）照常开发与独立验证；待材料或资源的内容项放入 `todo`/`backlog`，严禁在没有当前外部阻断事实时乱标 `blocked`。

### 4. 先做后讲、自己的题覆盖真题知识点且不直接放真题
- **决定**：核心学法确定为“选择题当课本，做中学，先做后讲”。
- **真题边界**：真题里的所有考点与知识点由独立拆解者提取，必须全部被我们自己的题库覆盖。
- **题库纯度**：题库与日常练习中**绝不直接放入真题原题或原卷**，防止换皮题或泄露，使用自编的高质量题目覆盖真题知识点，达成真正掌握。

### 5. 教材优先
- **决定**：在知识点定义、讲解内容、引用来源与判分标准中，**教材始终优先于课件和现实细节**。
- **引用权威**：备课包与阅读原文必须以权威教材为基准锚点，课件及辅助材料仅作扩展补充。

### 6. V7已定、一套风格派生
- **决定**：界面视觉定稿为 **V7（案头风格）**，已拍板定案。
- **变体策略**：沿 V7 同一视觉体系做高级感细节与明暗变体（外屏、内屏、桌面明暗风格），不再把 V1–V6 方案拿回去让李政挑选，不重选风格。历史讨论中的旧设计稿（V1–V6）仅作为档案保留。

### 7. 正式产品名 LearningCoach（2026-11-16 李政定）
- **决定**：正式产品名为 **LearningCoach**；以前用过占位名 LerningCoach。
- **旧候选处理**：严禁把 `Coutil`、`StudyCoach` 等旧临时候选词作为正式名称落盘。
- **名称范围与边界**：
  - 安装包、主窗口、导出文件名等使用 `LearningCoach`；顶栏字标可以简化，由 TON-1654 定稿。
  - **避免全仓替换 `Coach`**：严格保留代码仓库名（`coach`）、包名（package ID / bundle ID，如 `com.coach`）、代码包结构、签名与身份配置（沿现有配置、不改变身份）、MSI 升级身份、本地数据目录（`~/Coach`）、历史日志、事件账本及现有部署配置。
  - **不改构建版本、已装应用或凭据**。
  - **iOS 端集中配置**：iOS 未合分支（PR #119 / TON-1401）的名称只在既有 TON-1401 交接中指明集中配置，不擅改他人 PR。
  - **保留内容原貌**：严禁替教材正文、课程名或外部引用替换词汇。

### 8. 三移动形态+Mac/Windows、无Web、无产品工期（当前唯一开发范围Windows）
- **长期产品形态（保留不取消）**：
  1. 移动端覆盖三种形态：直板手机、Fold8 折叠屏、iPhone Duo。
  2. 原生桌面端：macOS 原生桌面、Windows 原生桌面。
  3. 长期产品形态保留为长期范围，不把当期暂停写成永久取消。
- **不做 Web 端**：明确不开发网页版。
- **不写产品工期**：不写虚假或倒逼的产品上线倒计时/工期，文案去除 AI 味，使用清晰朴素的人话。
- **当前唯一开发范围与当期排程**：
  - **当前唯一开发范围是 Windows**：
    1. 上传教材先读或直接学；
    2. 询问是否开启 learning；
    3. 出题可选（不出、选择、简答）；
    4. 学习位置打开阅读器对应原文；
    5. 阅读器翻真页。
  - **安装包排程**：安卓、iOS、Fold8、Mac 安装包暂停；Windows 安装包最后。

### 9. iOS已有账号内部TestFlight/直装不上架
- **决定**：iOS 端使用李政已有的苹果个人/企业开发者账号（签名团队沿现有配置、不改变身份）。
- **分发方式**：仅通过内部 TestFlight 或直接设备安装（Ad-Hoc / 内部体验），**不向 App Store 提交公开上架审核**。

### 10. 暂不合并Sable
- **决定**：当前明确**不与 Sable 合并代码或产品**。
- **技术隔离**：不复用 Sable bundle ID，不引入 Sable 生产依赖、账号或计费体系。仅借用其已验证的 iOS 签名流程实践。未来是否整合留作长期远期考虑，当前阶段严格独立。

### 11. 不测Mac睡眠，不反复索辅助功能授权，OPPO可替代样本
- **决定**：不测试 Mac 合盖睡眠场景（用户在开盖使用状态下使用软件）。
- **系统权限纪律**：不反复向用户索要辅助功能等系统授权（用户未找到系统入口，不造成打扰）。
- **测试设备替代**：移动端真机验证使用现有 OPPO 测试机（通过合法租约管理脚本 `~/Coach/testphone/wait.sh` 获取），不触碰私人 Fold8 手机，不绕过锁屏密码。

### 12. 阅读器兼容常见学习材料格式，不只 PDF 和 EPUB；2026-11-16 李政定
- **第一阶段**：保留 PDF、EPUB，支持 TXT（UTF-8、带 BOM 的 UTF-8、UTF-16 LE/BE、GB18030/GBK、Big5）、Markdown（含 `.markdown`）、Word（DOCX）、PowerPoint（PPTX）、保存的网页（HTML/HTM）、无 DRM 的 Kindle（MOBI/AZW3）、RTF、ODT。上传和拖入都能用；阅读、选段讲解、来源跳转沿用导入时保存的页文字与 UTF-16 偏移。
- **页与出处**：PDF、EPUB 保留现有切页方式；文本按章和文字块切页，Word 优先用分页符，幻灯片一张一页并保留备注。表格和脚注保留为可学的文字；加密、版权保护、损坏材料给出具体原因与处理办法。
- **第二阶段**：第一阶段合并后，再为扫描版 PDF、教材图片（PNG/JPG）加入文字识别。先用三份中英混排样例比较 Windows 自带 OCR 与打包 Tesseract 的准确率、速度、中文语言包可用性和模型体积，再实施，单独报告。识别文字按页保存，并明确提示可能有错字。
- **后续约定**：其他工单按本条推进，无需重复询问格式范围；不引入在线格式转换，不把受保护文件当成可读教材。

### 13. 朋友的 Windows 连李政的 Mac：Tailscale Funnel 只放讲解入口（2026-11-17 方案，正式服务与存储分工已由第 16 条更新）
- **前提（李政 11-17 定）**：服务端就是现在这台 Mac 上的 Coach 服务端，不迁 Sable、不买服务器；讲解走我们自己的 API（Haiku 5.5，按 TON-1632 的路由），花每月赠送额度。朋友的书留在朋友电脑上，讲解时只把选中的那段原文发到 Mac。
- **比较**（朋友不在李政的 tailnet 里）：

| 判据 | Tailscale 单机分享 | **Tailscale Funnel** | Cloudflare Tunnel |
|---|---|---|---|
| 朋友那边几步 | 装 Tailscale、注册并接受分享，再装 Coach 配对；常驻一个 VPN 客户端，可能和朋友自己的代理冲突 | 只装 Coach，填地址和配对码 | 只装 Coach，填地址和配对码 |
| 路由器开端口 | 不开 | 不开 | 不开 |
| 每个朋友能单独吊销 | 分享可撤 + Coach 设备凭据 | Coach 设备凭据（按朋友、按电脑） | Coach 设备凭据 |
| TLS 在哪里解开 | WireGuard 端到端 | **在 Mac 上解开**，Tailscale 中转只转发密文 | 在 Cloudflare 边缘解开，Cloudflare 能看到选中的原文 |
| 公网暴露面 | 没有公网面，但分享出去的是整台 Mac，要另写 ACL 才能只放一个端口 | 只转发到一个只挂讲解接口的本机端口 | 同左，但需要 Cloudflare 账号、域名、装 cloudflared；临时隧道地址每次重启都变 |
| 新服务 / 花钱 | 朋友要注册 Tailscale | 不注册新服务，免费 | 要 Cloudflare 账号，正式隧道要域名 |

- **决定**：用 **Tailscale Funnel**。Cloudflare 不用：TLS 在它那边解开，和「原文只经过李政的 Mac 发给 Anthropic / OpenAI」的承诺冲突，还要新账号和域名。单机分享留作备用：某个朋友那边打不开 Funnel 地址时，才给这一个朋友单独分享，并用 ACL 只放公网讲解端口。
- **公网入口只有一个本机端口**：服务端另开一个只绑 `127.0.0.1` 的公网端口（不是 18791），上面只挂：朋友配对、在线和今日余量、选段讲解、取消讲解。其他路径一律 404。Funnel 只指向这个端口，永远不指向 18791。朋友的设备凭据在任何端口上都只能用这几条；李政自己的设备凭据不在公网端口上用。
- **配对和身份**：沿用 6 位一次性配对码（5 分钟、最多试 5 次）。码按朋友签发：每个朋友有名字，每台电脑一个设备凭据；在 Mac 上能按朋友列出、按电脑或整个朋友吊销，吊销立刻生效。朋友导入的页、讲解记录按朋友分开存，不写进李政的学习记录。
- **花费**：每个朋友每天有讲解次数和 token 上限，Mac 上记每个朋友每天的次数、token 和花费。全体每月仍受 TON-1632 的 Coach 月上限约束（在赠送额度以内）；到月上限的 80% 在 Butler 面板提醒李政。朋友的讲解只走 API，API 不可用或额度用完时**不退回订阅 CLI**，客户端直接说「今天的讲解额度用完了」或「讲解服务暂时连不上」，不显示错误码。
- **Mac 不在线**：合盖、休眠、断网时，朋友那边提示「讲解服务暂时连不上，读书和做题照常」（做题如果也依赖 Mac，就只写读书照常），不卡住、不丢选中的段落。不改 Mac 的系统设置。`caffeinate -s` 只能在插电时阻止系统休眠，合盖照样睡，所以默认不开；要不要开由李政定，团队不擅自开。
- **隐私说明**：每本书第一次讲解前的同意里写清：选中的原文会经过李政的 Mac 发给 Anthropic / OpenAI 的 API（API 默认不拿数据训练），不发给其他地方。
- **公开仓库**：仓库是公开的。Funnel 地址、tailnet 名、配对码、设备凭据都不写进仓库、Actions 日志和评论；外网验证用的地址走 Actions 密钥。

### 14. Windows 并行验收采用开发专用进程内驱动（TON-1690，2026-11-17，尚待整轮验收）

- **当前可用入口**：前台动作继续使用 PR #390 的共享短锁，逐动作释放。PR #403 提供预编译 Runtime、调用状态和 Job Object 收尾；没有 `result.json` 就记调用失败，不填 N/7。PR #416 已合入 main ac4d7709，修复后台启动、滚动和选段入口。各次运行各用检出、数据目录和隔离服务；正式入口和后台开发入口分别验收。
- **A/B 实测**：在 winbox 真实 Coach 窗口上，以独立遮挡窗保持前台。A 的 loopback 控制读取真实 Skia 缓冲区，能打开设置、用 Escape 关闭，且前台保持不变；真实教材的启动、导入、翻页、段落讲解和出处弹卡也走通。B 的 PrintWindow(PW_RENDERFULLCONTENT) 对主窗及 Skia 子窗均返回成功，图中书架可读；向该子窗 PostMessage 鼠标消息返回入队成功，但按截图定位的设置控件未打开。本轮不把“消息入队”当成“UI 操作成功”，也不据此断言所有系统层实现都不可用。
- **选择**：继续 A。控件点击与键盘派发到各自 Compose 场景，图像来自实际窗口渲染。开发入口放在独立 smoke 源码集，只在显式环境变量打开时监听 127.0.0.1 随机端口；每次运行使用独立控制文件、令牌和 PID。正式应用源码集与运行时不依赖该入口。开发版选书回调把路径交给相同的正式导入逻辑，避免操作共享的系统文件选择框。
- **输入定位修复**：长选段会把提问框推到弹层视口下面。现在有界滚动到「想问什么」和字数计数同时可见，再点击两者之间的输入区；发送按钮按可见文字定位。没有改 Compose 正式输入实现，也没有放宽七步判定。OCR 标记使用纯字母数字，避免把下划线读成连字符造成假失败。
- **最终 main 实测（2026-11-17）**：ac4d7709 正式源码入口 7/7、exit0、223.39 秒（监工独立运行）；同一提交的后台 Runtime 单路 7/7、exit0、118.13 秒。后台四路与完整桌面 heavy 重叠时各 5/7、实际 exit1、224.08 秒，①②③④⑦通过，⑤⑥失败；四路均检出自己的标记，异路标记为 0。比值 1.90，未达 1.5；四路服务为 TON-1699 的 52ded01b 隔离服务，单路使用既有朋友服务，因此不能把差额全部归因于并发。此前的 3/7、候选 4–5/7、超时和无 result 均保留在卡上，不被本轮覆盖。
- **真实前台与资源**：四路 198 次采样中 heavy 活跃 192 次，CPU 峰值 100%，客户端合计 RSS 峰值 6.52GiB，可用 RAM 最低 5.00GiB；真实记事本有 44/198 次不在前台、5 次离开事件，持续前台未通过。四次事件对应本轮 heavy 测试 JVM，另一次对应 WindowsTerminal；不能把它们说成后台客户端抢焦点。单路客户端 RSS 峰值 1.59GiB，可用 RAM 最低 10.22GiB。
- **内存准入**：每个 smoke worker 在复制配对 seed 和启动客户端前申请 2GiB 预算，保留 3GiB 系统余量；共享短锁只保护准入记录。可用 RAM 已扣除了实际客户端 RSS，因此只再预留每个活跃 worker 尚未使用的预算。容纳不下就输出当前 RAM、前方 worker PID、2 秒重试和剩余等待上限，最多等 600 秒；到期不启动客户端，不伪造 N/7。退出释放自己的记录，异常退出按 PID 与 StartTime 清理陈旧记录。独立双进程回归 6/6、exit0；这不是 JVM 硬内存上限，也不证明任意教材下最大道数。
- **构建与剩余验收**：ac4d7709 的 Runtime 打包、正式包隔离和窗口几何定向检查经 Mac 默认 heavy 入口在 winbox exit0。此前完整桌面测试 598 项中 1 失败、10 既有跳过；失败为 `ReadableTextTest.noScreenTextShowsInternalIds`，干净 main 52ded01b 定向对照同样失败，未删除、跳过或放宽它。四路 7/7、1.5 倍、记事本持续前台及内存准入接入真实路径后的效果尚待补齐；⑤⑥隔离服务拒绝沿 TON-1699 原交接定位，不改题源或准入标准。

### 16. 本机优先，Hermes 负责处理、同步与恢复（李政，2026-11-26，TON-1886）

### 17. 每章一道开放题，逐点批改，答错回书再答（2026-11-26，TON-1910）

每章只出一道开放题。得分点三到六个，每个点只记住它在哪一页、哪一段、哪一句，模型不得把书里的原句抄进得分点。题用 Haiku 5.5 Batch 生成一次，写进这一章已有的练习草稿里，随学习记录同步，不再加新的表字段。朋友代读走 Haiku 实时，不走 Batch，避免把批处理记到别人的额度上。

批改沿用原来的逐点批改，不另起一套。每个点只给三种结果：答到、部分、没答到，各配一句话。没答到的点再给一个原因：没读到、读了没懂、混淆了别的概念、表达不清，并跳回那一页的那一句。答非所问不能被判成答到；这道闸门只会把模型给高的分降下来。答完可以再答一次，第二次只批上次没答到的点，两次都留在学习记录里，到两次为止。

服务端路由随这次改动一起提交。正式服务仍等主会话升级 Hermes 之后才对外可用。

### 18. 考点题先经另一家模型核对，对不上就不入库（2026-11-26，TON-1911）

教学式单选和论述提纲由 Haiku 5.5 Batch 写出。另一家模型独立作答，看不到标准答案、理由和出题引用。字母或出处对不上，只再问一次；仍然不一致的题不入库，界面写明该考点还缺几题。有教材时引用必须落在教材原句。往年题只提取考法，不进题库。学生先做选择题，选完才看每个选项为什么对或错。倒计时每日任务和限时模考不在这条里。服务端上线等主会话，不在本卡部署。
