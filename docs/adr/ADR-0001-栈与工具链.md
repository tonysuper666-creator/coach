ADR-0001 栈与工具链

状态：已决定（2026-10-29，Mika）。关联：分歧 d5、d8（服务端一半）；共识 C#5、C#18。

## 背景

栈已由李政拍板：KMP + Compose Multiplatform（安卓原生 + macOS，之后 Windows），服务端 Ktor（JVM）。未定的是版本组合与本机能否离线构建。核查员实测（`committee-result.json` d5，置信度 high）：缓存里只有 BiliPai-Windows 用的 CMP 1.12.1 / Kotlin 2.4.0 桌面依赖；安卓一半完全没缓存，且要求 compileSdk 37，本机 SDK 只有 34/35；Compose 桌面在本机 macOS 27.2 beta（26B5112a）上实测可用（Metal、中文与 emoji 字体回退、jpackage 出 .app 能启动）。

## 决定

1. 桌面端锁 Gradle 9.5.0 / Kotlin 2.4.0 / CMP 1.12.1（material3 1.12.0-alpha03）；`libs.versions.toml` 显式钉 lifecycle 2.11.0、kotlinx-serialization 1.11.0、androidx.navigationevent 1.1.2，桌面端可 `--offline`。不写「S0 取当日最新稳定版」（1.12.2 没缓存）。
2. 安卓：compileSdk 37、AGP ≥9.1.1（缓存有 9.3.2）、minSdk 26、targetSdk 35。S0 排一次联网同步（sdkmanager 装 platforms;android-37 与 build-tools、下载 CMP 安卓构件），超 10 分钟的命令用 `screen -dmS`。
3. 模块：`shared/{domain,protocol,client,ui}` + 独立 `androidApp` + `desktopApp` + `server/{app,core,store,content,ai}`（AGP 9 硬性要求安卓应用独立模块）。
4. 服务端 SQLite：sqlite-jdbc 锁稳定版 3.53.4.0（不用当天新发的 3.54.1.0）；FTS5 + trigram 可用，S0 冒烟验证。
5. 客户端库：SQLDelight 2 + 系统 SQLite；M1 搜索只走服务端（Android 系统 SQLite 无 FTS5，见 ADR-0006 附注与 DESIGN §7.2）。
6. JDK：Homebrew OpenJDK 17；换 JBR 或 JDK 21 时要重测输入法组字回车。

## 对核查员建议的裁决

- 全部采纳 d5 建议 1–6。
- d8 建议 2 的「二选一打包 SQLite」：**推翻为推迟**。M1 明确「搜索只走服务端」，打包 SQLite 推到 M2。理由：离线搜索不在 M1 闭环里；requery 驱动或 alpha 的 BundledSQLiteDriver 都会增加 M0 风险，而收益在 M1 用不到。
- 不采纳 O 原稿「首次下载 1–2GB」与 Opus 评审「完全不用下载」两种说法，以核查员实测为准。

## 后果

- S0 是所有 Gradle 类卡的前置；桥副本与 mathsvc 不依赖 S0，可并行。
- Compose 插件打包任务首次联网取 `gradle-plugin-internal-jdk-version-probe:1.12.1`，S0 一并做。

## 验证（S0 判定）

一个仓库同时产出 APK（装到 `sable-api35` 启动）与 Mac `.app`（启动）；桌面端 `--offline` 构建通过；JVM 上 `sqlite_compileoption_used('ENABLE_FTS5')=1` 且 `fts_en`/`fts_zh` 建表并能用「逆向选择」「adverse selection」「Grossman」查到行；SQLDelight 编译含 `fts5(..., tokenize='trigram')`、`MATCH ? ORDER BY rank` 的 `.sq`（编不过的语句改用 `driver.execute` 原生 SQL）。
