ADR-0002 订阅桥副本 8791 与首字口径

状态：已决定（2026-10-29，Mika）。关联：分歧 d2、d3；共识 C#13、C#14。

## 背景

现役桥 `~DT/tools/subscription_bridge.py`（8790）服务 DeepTutor，期中前必须稳定。核查员读码并在桩 CLI 上故障注入（d2，置信度 high），确认 Astra 列的四条缺陷全部成立：没注册 Grok（MODELS 在 L44–49）；只有 Claude 的非 JSON 请求是真流式；兜底后回包 `model` 仍是请求值；出字后超时/异常仍发 `finish_reason:"stop"` 和 `[DONE]`（L429–434、L692、L723–737）。另有新发现：排队时间被算进首字超时；挂起超时造成的截断桥自己的日志也记成 ok；真实 max_output_tokens 截断不报 length；副本路径（LOG_FILE/CLAUDE_CWD/AGY_BIN，L24–30）指向 ~/DeepTutor 并依赖 DeepTutor 的 venv；两份桥各有信号量，Claude 实际并发会到 6。

首字（d3，置信度 medium）：60K 字以下，决定首字的是请求类型而不是备课包大小。开讲时 Sonnet 5.5 的自适应思考先跑 7–9 秒，首字 9–18 秒，12K 也一样；只有追问与简单问答在 ≤40K 时能 ≤5 秒。

## 决定

1. Coach 仓库 `tools/bridge/` 放副本，跑 8791；DeepTutor 的 8790 一个字不动。副本必改九项（照 d2 建议原文）：
   (1) 路径迁出：`COACH_BRIDGE_HOME`，日志/cwd/临时文件都在 Coach 目录；沙箱包装与 `.sb` 复制进来再审白名单；Coach 自己的 venv。
   (2) 显式终态：`[DONE]` 前最后一帧 `x_coach={status: complete|truncated|failed, reason: timeout|cli_exit|max_output_tokens|client_gone, served_by, fallback, physical_calls, request_id}`；中途失败 `finish_reason` 为 `length` 或 `error`，不再发 `stop`；按 Claude result 的 is_error / terminal_reason / api_error 判定。
   (3) `served_by` 取 CLI 自报的实际模型，写进回包 `model`、`x_coach` 与非流式的 `X-Served-Model` 头。
   (4) `X-Coach-Fallback: off`，Coach 默认关隐式兜底，兜底由 Coach 显式发起并计入预算。
   (5) 回显 `X-Request-Id` 并写日志；按请求设推理强度（Claude `--effort`、Codex `model_reasoning_effort`、Grok `--reasoning-effort`）。
   (6) 超时从拿到信号量后起算，排队时长单独记。
   (7) 并发：副本 Claude 上限 2，后台最多 1；读 `rate_limit_event`，utilization ≥0.8 或 status≠allowed 暂停后台生成。
   (8) `/v1/models` 标 `true_stream`；Codex 标 false，界面显示等待、不模拟打字；agy 默认关；Grok 未 live 实测前不注册为导师。
   (9) 桩 CLI 故障注入（kill -9 中途、挂起超时、拒答兜底、max_output_tokens、4 请求排队）做成副本的回归验收，另配一组非学习时段 live 测试。
2. 首字按请求类型验收：追问/问答（备课包 ≤40K）客户端看到正文首字（不含「还在想」等进度帧）n≥20，p50 ≤5 秒、p90 ≤8 秒。开讲走预生成（DESIGN §5.2），报告命中率与未命中的实时 p50。
3. 时限：首字截止 25 秒，8 秒显示「还在想」；截止后 Coach 显式调 Codex 非流式并显示真名；流总时长 180 秒；30 秒无新 delta 判卡住；JSON 输出 ≤4K 字 90 秒。
4. 备课包上限维持 ≤40K 字 / ≤6 页（按教学与引用需要定，不为延迟压到 12K）；避免超过约 100K。
5. 不为延迟提前做 Kotlin CliProvider（CLI 启动只占 0.5–1.6 秒）；维持 O §5.5 的替换触发条件。

## 对核查员建议的裁决

- d2：全部采纳，**加一条期中保护**（推翻「后台最多 1 个 Claude」在期中前的取值）：至 2026-11-02 14:25，副本 Claude 并发上限 1、后台生成全部走 Codex；每批 live 测试前只读看 `~DT/data/user/runtime/bridge.log` 最后一行时间，10 分钟内有活动就推迟。理由：他这几天在用 DeepTutor 复习，两份桥共用同一 Claude 订阅，Coach 的开发不能让他的复习排队或被限流。
