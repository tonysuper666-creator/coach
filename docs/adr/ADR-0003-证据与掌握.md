ADR-0003 证据与掌握

状态：已决定（2026-10-29，Mika）。关联：分歧 d4、d6；共识 C#6、C#7、C#8、C#10、C#11、C#12。

## 背景

- 已通过窗口（d4，置信度 medium）：DT 的 5 次加权窗下答错一次后要再连对 5 道新题（[错,对,对,对,对]=0.875）。核查员穷举确认「最近 3 次有效首答全对」不会让 DT 里已通过的点掉级；10-28「答多少遍都过不了」的真因是定性门，不是 5 窗。
- 题池供给（d4）：小 spike 实测生成 + 盲复核约 0.8 次物理调用换 1 道已复核题，3 道一批 p50 约 21 秒；「铺池要 2–3 天」只是 O 自设的每天 60 次上限算出来的；全部 49 KP 铺满约 120 次调用、15–20 分钟。Astra 的同步出题每次等 20–40 秒，与零等待冲突。
- 逐字证据（d6，置信度 high）：照搬 SC 阈值（≥3 词元、≥8 有效字符，`SC/packages/ai-runtime/src/grade-validation.ts` L12–19），用他的真实中文作答测误拒率 72%（13/18）；修好 SC 的单字 bug 也只降到 67%；Astra 的「无门槛」写法对截断类伪证 14/14 全部放过。

## 决定

1. 已通过 = 最近 3 次有效首答全对（选择题精确对；构答得分率 ≥0.8），题目指纹互不相同、答案键已复核；带提示的作答排除在窗口外（不按半分）——「带提示」= 有任何 `hint_revealed`，cause 为 BUTTON 或 LEAK 都算 〔验收 TON-1045 #2〕；通过后锁存。DT5 加权分只作展示。窗口按服务端 seq 排序。迁移来的作答（origin=LEGACY）永不进任何窗口，只靠 `legacy_passed` 锁存和展示；108 题复核通过后也不回溯计入 〔评R3 I4〕。
   锁存按事件顺序判定 〔评R3 I5、m5〕：有效性的变化（`grade_reviewed`、`attempt_voided`、`question_key_changed`）本身是事件；锁存在每个事件处按截至该事件已知的有效性判定，复核晚到时锁存在复核事件那一刻成立、不往回改。锁存只抵抗「之后答错」，不抵抗「证据本身被作废」：作废或答案键被判错后，若支撑集不足 3 条，就在作废事件处撤销，记录页写原因。
2. 稳固 = 合格证据 ≥2 条、其中 ≥1 条构答、跨 ≥2 个逻辑日、均值 ≥0.85；合格条件见 DESIGN §2.2：必须是有效首答，并且 `hints = 0`（同时计 BUTTON 和 LEAK，即无任何 `hint_revealed`〔验收 TON-1045 #2〕）、非 assisted，删掉沿用 SC 的 `hints <3`（否则点过 1–2 次提示的闭卷构答进得了严格层、进不了冲刺层）〔评R3 I2〕。M1 没有模考，单选题不合格，所以 **M1 下稳固 = ≥2 条有效构答** 〔评R3 I1〕。稳固 ⇒ 已通过；迁移与手动标记永不产生稳固。复习队列只含已通过的 KP，所以复习合格作答可计入稳固，而复习 FAIL 不撤销已通过（修 Astra 评审指出的 O 的三条规则冲突）。
3. 取消「有待答题时导师每次回复都算提示」。`hint_revealed` 只有两种 cause：BUTTON（用户点「要提示」）与 LEAK（泄题检测命中），两者对两层的效果相同〔验收 TON-1045 #2〕；待答时追问使该作答成为 assisted：不影响已通过，不算稳固证据。assisted 由投影计算，不写进 `answer_submitted` 载荷：按 seq，该 attempt 出题之后、作答之前若有 `pendingAttemptId` 等于它的 `followup_asked`，即为 assisted（跨设备追问也能判对）〔评R3 I3〕；选择题另做确定性泄题检测，命中记 `hint_revealed cause=LEAK`。
4. 题池：当前 KP、后两个 KP、今日到期 KP 各常备 ≥3 道未见过的已复核选择题；未见题 <3 或刚答错时立即补一批（1 次 Claude 出 3 道 + 1 次 Codex 盲复核）；当前 KP 补题算前台；被弃题并入下一批；预算报告「按批平均每道已复核题物理调用数」（目标 ≤1.5），60 次/天从硬上限改为报告值；同步出题否决，「完整验证后才发布」放到后台执行。
   构答题供给 〔评R3 I1〕：KP 一旦已通过，后台为它补 ≥2 道已复核构答题（冻结 rubric，rubric 经异厂复核）；按需补，不预先给 49 个 KP 全备；调用预算见 DESIGN §5.2。还没有构答题的 KP，路线页标「此 KP 暂无构答题」，稳固层到不了——如实显示，不降低标准。「已复核变式」的定义见 DESIGN §2.4。
5. 出题时的原文逐字引句检查：对公式与 Markdown 先规范化，或改为核对页码锚点，避免把推导题误弃（d4 建议 5）。
6. 逐字证据（照 d6 建议 1–8）：保留 SC 的 rubric 冻结、「必须是原答子串」、NFKC + 空白归一；加减号统一（U+2212、U+2010–2015、U+FE63、U+FF0D → `-`）；三类词元（汉字单字 / 整个数字 `[+\-]?\d+([.,/:]\d+)*%?` / 连续拉丁字母，不吞后面的汉字）；起止落在词元边界；门槛 = 有效字符 ≥8，或恰为整个分句（≥2 有效字符，分句按空白与中英文标点切、不在数字内部切），或就是整个答案；区间由服务端算、存 UTF-16 `[start,end)` 并存原文片段；从 DeepTutor（Python 码点）迁入先换算；失败带原因修复一次，仍失败 = 批改不可用、不写掌握。批改 prompt 写明：逐字照抄整个分句、保留错别字与语音输入错误、不改写、不给偏移量、数值答案连同所在分句一起引。
7. 计算题终值由服务端数值比对（带容差，解析常见中文数字），AI 只批过程（采纳 d6 建议 9，原为「待团队裁决」）。
8. 进入稳固的构答批改必须经不同厂商复核，复核看到完整答案与证据并同意才算；不确定或复核不成 → 不写任何一层（fail closed）。
9. 已知局限（写进设计，不假装解决）：否定句、自我更正这类语义伪证任何长度规则都挡不住，只能靠异厂复核。泄题检测只覆盖选择题；构答题「先问导师再答」能过已通过（assisted 只挡稳固），单用户的冲刺层可以接受 〔评R3 推翻意见 2〕。
10. 回档后的作答 〔评R3 F1〕：`submit_answer` 自带出题快照（attemptId、questionId、fingerprint、kpIds、purpose、policyVersion）；服务端遇到未知 attempt 按快照补写 posed；题目本身也不在了，就存成「孤儿作答」（`answer_orphaned`）：保留原文、不计分、不进任何窗口，记录页可见（沿用 O §4.4）。完整回档规则见 DESIGN §4.3。

## 对核查员建议的裁决

- d4：建议 1–6 全部采纳；**建议 1 中「取消自动记提示」部分采纳**：取消对已通过的影响，但加 `assisted` 标记挡住稳固。理由：完全不记，会让「问完导师再答」成为稳固证据，严格层失去意义；只挡稳固则不影响冲刺，也不重现 10-28。
- d6：建议 1–8、10 采纳；建议 9（服务端数值比对）由「待裁决」改为「决定」，M1 实现。理由：「0.25 / -0.27 / 负十一分之三」这类终值交给模型判既慢又不稳，确定性比对更符合「掌握由纯规则写」。

## 后果

- 108 题里未复核通过的题不计任何一层；M0 的出题与批改 spike 要把 60 道选择题逐批盲复核入池。
- 黄金用例：3 窗口语义、中文短答、`assisted`（由投影算，含跨设备追问）、点过提示不进稳固、复习不撤销已通过、LEGACY 作答永不进窗口、作废后撤销锁存与复核晚到（账本卡）〔评R3 I2–I5〕。

## 验证

- 出题与批改 spike：植入 5 道错键题全部被盲复核拦下；植入非原文证据与截断证据全部被拒；他的 5 条真实作答（#71/93/95/99/139）全部通过逐字校验；M0 只报 AI 批改与异厂复核的一致率（20 道简答与人工评分的对照在 M1 由他抽查时补，见出题与批改卡）；模拟「答错一次」下一题等待 ≤10 秒；顺带测构答题供给：每道已复核构答题的耗时与物理调用数 〔评R3 I1〕。误拒率只报告，不设卡。

## 修订（2026-10-29 晚，DeepTutor 使用复盘 `docs/lessons-from-deeptutor-usage.md`）

- 决定 4 的题池：当前 KP 常备 ≥6 道（默认一组 3 道、一次提交，DESIGN §5.8 第 7 条），其余 KP 仍 ≥3 道；每个 KP 不论类型都要有选择题供给，保证「已通过」只靠选择题即可达成（复盘 §5）。
- 选择题不存字母：答案键引用 `optionId`，字母在 `question_posed.letterMap` 里由服务端分配（复盘 §1）。指纹按排序后的选项文本算，与字母无关。
- 不改变任何掌握判据：同一组的 3 道题各自独立判分、各自按 seq 进窗口。
