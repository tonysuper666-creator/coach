ADR-0004 传输与鉴权

状态：已决定（2026-10-29，Mika）。关联：分歧 d7；共识 C#16。

## 背景

核查员实测（d7，置信度 high）：方案 A（Tailscale IP 明文 + Android 网络安全配置例外）成立——模拟器上 domain-config 写 IP 字面量或 MagicDNS 名都能放行 HTTP 与 WS，未列出的地址照样被拦。方案 B（`tailscale serve` HTTPS）技术上可行（本机是官网独立版，WS 经 Go ReverseProxy 透传），但他的 tailnet 没开 HTTPS 证书，要他改 tailnet 设置、接受机器名进公开证书日志、手机开 Tailscale DNS。Opus 评审说的开机绑定失败属实，但它给的「改用 MagicDNS 名」在这台 Mac 上行不通（Tailscale DNS 关着）。

## 决定

1. 默认方案 A。Android：base-config 禁明文；domain-config 只放行 Mac 的 Tailscale IP，可再加 `<domain includeSubdomains="true"><tailnet>.ts.net</domain>` 以便迁机（IP 与 tailnet 名在构建时从本机配置注入，不入仓库）；客户端首选 IP 字面量。不照搬 DeepTutor 壳的全局 `usesCleartextTraffic=true`。
2. 监听拆两路：`127.0.0.1` 启动即绑；Tailscale IP 由监督协程按退避反复重绑（可先轮询 `tailscale status --json` 等 BackendState=Running），绑不上不拖垮服务。不绑 0.0.0.0。Mac 唤醒后（检测方法见 DESIGN §4.7）也检查一次 Tailscale IP 上的监听，失效即交给监督协程重绑 〔评R3 I7〕。
3. 安全来自两层：WireGuard + 设备令牌。6 位配对码（5 分钟有效）换 256 位令牌，服务端只存 sha256，逐台吊销；令牌只放请求头。本机回环请求也必须带令牌（Mac 桌面端令牌文件 0600 自动配置）。
4. 方案 B 不在 M1 做，留作「建议，待他裁决」；真要做时先请他开 HTTPS 并说明公开日志，再确认两台安卓设备开了 Tailscale DNS。

## 对核查员建议的裁决

- 建议 1、2、3、5 采纳。
- 建议 4（`tailscale serve --tcp` 转发、不改 tailnet 设置）：采纳为 S0 的一项实测（核查员只读了源码，未实测），若可行可替代重绑协程——这是工程选择，不请他定。
- 建议 3 的「不能把来自回环当免认证」提前到 M1 就执行（决定 3），这样将来改走 serve 时不留鉴权缺口。

## 附注：Ktor 引擎选型（DESIGN §14 #7，M1-01 定）

2026-10-30，M1 第一张卡（TON-1087）在同一负载下把 Netty 与 CIO 各跑一遍。负载是桩桥（不调真实订阅 CLI）：每条消息三帧正文 + 终态帧、帧间隔 10 ms，客户端是 JDK WebSocket，量的是**客户端看到正文首字**（`msg.ask` 发出 → 第一帧 `msg.delta` 到达）与**断线重连拿到 `msg.snapshot`**，与 M1-01 的验收口径同一把尺子。

| 引擎 | n | 首字 p50 | 首字 p90 | 续传 p50 (n=5) |
|---|---|---|---|---|
| Netty | 20 | 17 ms | 19 ms | 0 ms |
| CIO | 20 | 17 ms | 18 ms | 0 ms |

结论：**保留 Netty**。两者在这条链路上的数据在噪声内（差 1 ms），首字与续传都不构成选型理由；决定靠运行时约束：
- 服务端要同时跑回环与 Tailscale 两个引擎、并对失效监听做退避重绑（本 ADR 决定 2），这条监督逻辑与 `connectionGroupSize/workerGroupSize/callGroupSize` 的收缩配置已经在 Netty 上跑通并有测试；
- 换 CIO 要重做线程池收缩与重绑验证，收益是 0 ms；
- CIO 的 WebSocket 实现比 Netty 少一条成熟路径，出问题时要连引擎一起怀疑。

真实模型下的首字已于 2026-10-30 复测（见下文）；将来如果出现「多路并发流把 Netty 的小线程池打满」的证据（例如同一时刻 4 条流各段耗时同步变长），再按本附注的同一方法复测 CIO 并回来改这一条。测量命令：`./gradlew :server:app:test --tests "com.coach.server.EngineBenchTest" -i`。


2026-10-30 独立复跑（Builder，`tools/dev/heavy ./gradlew :server:ai:test :server:store:test :server:app:test --max-workers=2`，65 条，0 失败）：Netty 首字 p50/p90 **17/19 ms**、续传 p50 **1 ms**；CIO **15/18 ms**、续传 **0 ms**（仍各 20 次首字 + 5 次续传）。两毫秒的差异不改变上述运行时选择；继续保留 Netty。
