ADR-0006 DeepTutor → Coach 迁移

状态：已决定（2026-10-29，Mika）。关联：分歧 d8；共识 C#17；漏#4（切换与回退）。

## 背景

核查员（d8，置信度 high）：`?immutable=1` 会跳过 WAL、不加锁，读一个还在运行的库会得到旧数据或错误数据；应改 `mode=ro` + 单个读事务，或先 `VACUUM INTO` 出快照再读。两个库（`mastery.sqlite3`、`chat_history.db`）无法在同一原子时刻快照。`mode=ro` 会在 DeepTutor 的 data 目录里留下 `-wal/-shm` 文件（无害，但不再算零写入）。17/20 差异：作答事实以 `mastery_interactions` 与 `mastery_events`（20 条）为准，缺证据的 3 条同属一个 KP、发生在 10-28 大纲合并之前。Astra 评审：源记录修改后「源 ID + 内容 hash」会生成第二份学习事实，需稳定源 ID 与修订关系。

## 决定

1. 工具 `tools/migrate-deeptutor`，只读、幂等、可重复、可增量，提供 `--dry-run`（打印计数与差异）。
2. 读法分两段：
   - **期中前（≤2026-11-02 14:25）**：不对 DeepTutor 数据目录打开任何 SQLite 连接。在 DeepTutor 空闲时用 `cp` 把库文件（含存在的 `-wal`）拷到 `~/Coach/migrate-staging/<时间戳>/`。有效拷贝的判据 〔评R3 m6〕：拷贝前后对 db 和 `-wal` 各做一次 stat（size + mtime），一致才算有效，否则丢弃重拷（DeepTutor 服务常驻时 `-wal` 一直在，原判据「无 `-wal`」几乎不会成立）；不拷 `-shm`；`courses.json`、`journal.json`、`notebook/` 在同一个空闲窗口里一起拷。对拷贝跑 `PRAGMA integrity_check`，之后只读拷贝。
   - **期中后**：`file:...?mode=ro` 打开 + `VACUUM INTO '<暂存>/x.snapshot.db'`，所有读取对快照做；幂等键带快照 sha256。
   - 最终切换那次：先停 DeepTutor 或确认空闲，再核对跨库关联（如 assessment_attempts 对应的 interaction 都存在）。
3. 稳定源 ID：`legacy:{source}:{table}:{pk}`，`{source}` 取库文件名（如 `mastery.sqlite3`、`chat_history.db`），否则两个库的主键会撞 〔验收 TON-1045 R1〕；源记录内容变了 → 写修订，不新增首答。
4. 映射照 `O §10`，修改：5 个已通过 KP → `legacy_passed`（直接锁存，不依赖新公式）；20 条作答（17 + 3 条标「大纲合并时重置」）——迁移来的作答一律永不进任何窗口（已通过、稳固都不进），只靠 `legacy_passed` 锁存和展示，108 题复核通过后也不回溯计入 〔评R3 I4〕；108 题归属 KP 用「章 → 模块 → 页码重叠 → 模型选并盲复核」；`topic_dd61…` 路径不导入、原 JSON 存档；期中分值覆盖表 → `exam_weights_set`；sealed、「答案」目录不导入索引与导师上下文。
5. 对账报告逐项列计数与差异解释：49 KP、108 题（60/48）、20 条作答、5 条复习、12 条笔记、5 个已通过。另加一行核对：`legacy_schedule` 里 KP 不在 `legacy_passed` 的，不进复习队列（复习队列只含已通过 KP），在报告里逐条列出 〔评R3 m8〕。
6. 切换与回退照 DESIGN §11.1：期中后首次正式迁移；增量重跑到切换日；切换不在考前 7 天内；切换前连续 2 次增量对账零差异；切换后 DeepTutor 原样保留两周，回退零成本。

## 对核查员建议的裁决

- 建议 5（`mode=ro` + `VACUUM INTO`）：**期中后采纳，期中前推翻为「拷贝后再读」**。理由：立项卡约束「期中前不要动 DeepTutor 的运行文件」；`mode=ro` 会在其 data 目录留下 `-wal/-shm`，虽然无害，但期中前我们选零接触。拷贝在空闲时做并经 `integrity_check`，一致性风险可接受，而且 M0 只做 dry-run 对账，不写任何正式学习事实。〔评R3 推翻意见 4〕同意，并加上 m6 的 stat 一致性判据（决定 2），让拷贝结果可验证。
- 建议 6（17/20）：采纳。
- 建议 1（sqlite-jdbc 锁 3.53.4.0）、2（Android 无 FTS5）、3（SQLDelight FTS5 语法）、4（中文检索 trigram + 短词 LIKE）：采纳，分别落在 ADR-0001 与 DESIGN §4.2、§7.2；建议 2 的「打包 SQLite」按其备选推迟到 M2（见 ADR-0001）。

## 后果

- M0 的迁移卡只产出对账报告与映射候选，不写正式 Coach 库。
- 迁移卡与账本卡可并行：迁移卡产出的是映射 JSON 与报告，接入账本在 M1。

## 验证（迁移对账 spike 判定）

每次拷贝报告前后两次 stat（db、`-wal` 的 size + mtime）且一致；dry-run 对拷贝跑两次输出字节一致；对账报告每个计数与源库手工 SQL 一致并解释差异；108 题 KP 归属给出自动可得率与需人工确认清单；运行期间 DeepTutor 数据目录 `ls -la` 前后无新增文件、mtime 不变。
