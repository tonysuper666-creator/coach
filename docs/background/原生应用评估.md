# 做成原生应用：难度评估（2026-10-29）

结论先说：**真正的原生（Kotlin）应用值得做，但不该现在做，也不是最划算的第一步。** 最划算的是三档里的第二档：用 StudyCoach 的设计语言重写一个只含我们在用功能的轻前端，仍然连 DeepTutor 的后端，外面套现在这个安卓壳。原生放在期中（11-02）之后再决定。

## 一、我们实际在用的功能（要保留的范围）

从聊天记录、事件库和接口看，日常只用到：

1. **精通路径概览**：模块与知识点大纲、进度、“下一个”按钮、精通会话列表。
2. **学习会话**：流式聊天（Markdown + 公式）、选择题卡片（点选、跳过、问导师）、四位导师的选择。
3. **复习**：间隔复习入口。
4. **主页聊天**：随手提问。
5. 次要：阅读集、笔记本、练习题库、复习书（目前主要通过聊天里的“交接”进入）。

DeepTutor 原界面还有伙伴、任务看板、智能写作、子智能体设置、知识库管理等，我们没用，可以不做。

## 二、后端接口的规模（做新前端要对接的东西）

- 精通路径路由约 1,300 行，常用的是：路径详情、地图/大纲、各知识点详情、会话列表、复习设置、进度与事件。
- 聊天和精通会话各有一个 WebSocket（`/ws`、`/ws/mastery-paths`）。我统计了现有对话里实际出现的事件，只有约 10 种：`content`（流式正文）、`progress`、`tool_call` / `tool_result`（含选择题卡片）、`stage_start` / `stage_end`、`result`、`done`、`error`、`session`。数量不多，协议不复杂。
- 风险：这些接口是 DeepTutor 的内部协议，没有稳定性承诺。升级 DeepTutor 可能改字段；我们已经靠 6 处补丁在维护它，新增一个客户端会再加一层依赖。

## 三、StudyCoach 的风格能借什么

我拉下了归档仓库来看（只读，没编译）：

- **技术栈**：React 19 + Vite + react-router + lucide 图标，设计令牌放在 `packages/design-tokens/tokens.css`。前端体量不大（Web 版 38 个组件文件，桌面版 156 个）。
- **视觉**：暖纸色底（`--warm-50: #f4efe6`）、粉色主色（深粉 `#c94b7c`）、薄荷绿辅色、衬线展示字体（Iowan Old Style / 宋体系）加无衬线正文，大圆角（12/18/28px）、毛玻璃顶栏、克制的动效（120–320ms）。令牌分三层（标度、调色板、语义），规则严格。
- **产品形态**：全课程块状路线、逐步教学、练习批改、掌握度与间隔复习、每天一篇学习日记。这些和 DeepTutor 的掌握路径是同一类东西。
- **可直接复用**：令牌 CSS、按钮/卡片/顶栏样式、字体选择、动效节奏，以及“块状路线”“学习日记”这类交互思路。
- **不能直接复用**：它的后端（learning-api、control-plane 等六个服务、Rust 的内容存储和 SQLite 持久化）规模很大，而且早已冻结。重启后端的代价远高于重写前端，不建议。

## 四、三档方案与难度

| 档 | 做什么 | 难度 | 估算（我带 AI 协助，一个人） | 主要风险 |
|---|---|---|---|---|
| 0 | 现在：WebView 壳 + 手机入口脚本 | 已完成 | — | 靠修补 DeepTutor 自带界面，改一处可能牵动另一处 |
| 1 | 在手机入口里注入 StudyCoach 的设计令牌，把 DeepTutor 的界面“换皮”（暖纸色、粉色、衬线标题、圆角） | 低 | 0.5–1 天 | 只能改颜色、字体、间距，布局逻辑改不了；DeepTutor 升级后选择器可能失效 |
| 2 | 新写一个轻量 Web 前端（React + StudyCoach 令牌），只含概览、会话、复习、主页聊天四块，连现有后端，仍放进安卓壳 | 中 | MVP 3–5 天，打磨到“丝滑”再加 1 周 | 对接内部协议；选择题卡片、公式渲染要重做（浏览器里用 KaTeX，相对容易） |
| 3 | 真原生：Kotlin + Jetpack Compose，连同一后端 | 高 | MVP 2–3 周，打磨到可日用 4–6 周 | 见下 |

### 档 3 的难点

1. **公式渲染**：Compose 没有现成的 LaTeX。通常的解法是每条消息内嵌一个小 WebView 跑 KaTeX，或者用 JLaTeXMath 之类的库。体验和性能都要调，是最难的一块。
2. **Markdown 与流式滚动**：边流式追加边渲染 Markdown、表格、代码块，还要保持滚动位置不跳。
3. **折叠屏四种形态**：Compose 的窗口尺寸类和列表-详情面板对折叠屏支持很好，这是原生相对最大的优势，外屏、内屏竖屏、内屏横屏、折叠切换时的状态保持都能做得很稳。
4. **协议维护**：要在 Kotlin 里重新实现 WebSocket 客户端、事件解析、重连、选择题卡片状态，和 DeepTutor 升级长期对齐。
5. **没有网页的“免费午餐”**：目前很多页面（设置、阅读、笔记本）直接用网页版；原生要么重做要么内嵌网页，混用会有风格割裂。
6. **工具链**：本机已有 SDK、模拟器和构建脚本，但没有 Gradle 项目；需要引入 Compose 依赖（要联网下载）。

### 原生相对网页的真实收益

- 折叠/展开、键盘、手势更跟手，没有网页那种细微卡顿；
- 通知、桌面小组件、后台保活（例如回答写完推送）；
- 离线缓存最近的大纲和对话。

这些是“锦上添花”，对备考不是刚需。

## 五、我的建议

1. **期中前（现在到 11-02）**：不动架构。只做档 1 的轻量“换皮”（如果你愿意，约半天），其余时间留给学习。
2. **期中后**：做档 2。它复用你喜欢的 StudyCoach 风格，只保留我们用的功能，LaTeX 用 KaTeX，开发快、风险低；同时把“我们改过什么”的修补需求降下来（新前端不依赖 DeepTutor 自带界面的 CSS）。
3. **档 3 视情况**：如果用了档 2 之后仍觉得卡顿，或者想要通知、小组件、离线，再单独评估。
4. **关于重启 StudyCoach**：我的建议是“继承它的设计语言和产品思路，不继承它的后端”。要不要真的重启，取决于你想长期用 DeepTutor 的掌握路径引擎，还是想要一个完全自己掌控的引擎；这个是我们评估时要先回答的问题。

## 六、需要你拍板的问题

- 先做档 1（半天，换皮）还是直接等期中后做档 2？
- 档 2 的范围先只做“路径概览 + 学习会话”两块，还是四块一起？
