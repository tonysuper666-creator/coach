# 你的任务：完整设计 Coach（你一个人对全部负责）

用户的要求：**三位成员（Opus 5.5、Sonnet 5.5、GPT-6-Astra）各自独立完成完整设计**，不分工；之后互相评审，再由主持人（Claude Code 主会话）比较、整合、裁决。所以请把自己当成唯一的总设计师：覆盖产品、领域、服务端、AI、协议、客户端、设计系统、迁移、测试、里程碑，并对每个重要选择说出**你的立场和理由**。不要因为别人也会写某部分就省略。

先读 ~/DeepTutor/design/brief.md，再按其中顺序读背景材料（够用即可）。

## 必须覆盖（按此编号组织你的文档，每节都要有“决定 / 建议 / 开放问题”之分）
1. **产品与学习闭环**：用户旅程（每天、考前冲刺、手机碎片、折叠展开切换、离线/Mac 休眠）；屏幕清单（今天/路线/学习/复习/记录/资料）与每屏的主动作、空状态、错误态；对话模型（每个对话挂什么对象、有几种、能/不能做什么、追问边界、多位导师如何出现而不让用户手选任何资源、“随口问”如何沉淀）。
2. **学习规则**：把 StudyCoach 的证据规则与 DeepTutor 的实际行为取舍成一套，给出具体阈值与理由——尤其“已通过（冲刺，选择题可过）”与“稳固（严格证据）”两层如何共存、前置依赖、阶段是否保留、复习队列（含题库）合一、日记结构、教学模式的自动/手动触发。
3. **领域模型与事件账本**：一等对象；事件类型清单（字段、幂等键、产生者、可否撤销）；投影（位置/掌握/复习/阶段/日记）的精确定义；版本化与迁移。写成能直接转 Kotlin 数据类的形状。
4. **服务端与存储**：Kotlin 模块划分与依赖方向；SQLite 表结构（含 FTS5、内容寻址、教材“PDF 页/书页”引用）；备份；租约与多设备冲突。
5. **AI runtime**：“备课→讲→出题→作答→判分→更新”的编排方式（沿用 tool-calling 提示协议，还是服务端驱动的结构化状态机？选一个并说明）；调用预算、独立复核、来源归属校验、逐字证据批改；流式事件格式；取消/超时/兜底链；如何复用现有订阅桥以及何时替换；怎样做到“真实验证而非 mock 冒充”。
6. **客户端-服务端协议**：REST+WS 端点与消息；按序号断点续传；离线作答队列的幂等；版本协商；认证（Tailscale 内网下最简又安全的做法）。
7. **客户端架构**：Gradle/KMP 布局与依赖选型（逐项理由与备选）；状态管理；导航；**流式 Markdown + LaTeX 渲染方案**（逐平台可行性、性能、滚动稳定）；离线缓存；构建与测试工具链在这台 Mac 的现状与缺口（JDK17 与部分 Android SDK 已有，Gradle/Kotlin 未装；已有 AVD sable-api35）。
8. **自适应与折叠屏**：窗口尺寸类 + 折叠姿态；按已知尺寸（Fold8 外屏竖约 475dp、横约 751dp；内屏竖约 704dp、横约 933dp；Pad Mini 竖约 750–840dp、横约 1120–1260dp，均为估算）给出每个断点的具体布局规则；折叠/展开时状态保持；键盘/IME 与流式输入。
9. **设计系统**：StudyCoach 令牌 → Compose 主题（颜色、中文衬线标题字体取舍、形状、动效、暗色、对比度）；组件清单与状态。
10. **DeepTutor → Coach 迁移**：逐表/逐对象映射（课程库、49 个知识点大纲、108 题、笔记本、掌握记录、学习日志、会话）。
11. **测试与验证**：领域属性测试与黄金用例；UI 如何测到“用户感知到的质量”而不是记账式断言；AI 链路的真实端到端验证。
12. **里程碑、spike 顺序与判定标准、风险**；以及“第一版不做什么”的清单；以及怎么把工作拆给一支 agent 团队（岗位：架构师、工程主力、前端/安卓、验收）并避免互相踩踏。
