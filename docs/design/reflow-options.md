# 文字阅读保留特殊排版：本机方案比较

2026-11-16，TON-1669 第一阶段的局部结果。**没有完成四路比较，也没有完成阅读器验收。**

目标是让正文可以重排，同时让表格、公式、知识框和示意图保持原样，并保持既有出处、
高亮和批注的 UTF-16 偏移。用同一批真实教材页验证候选区域，而不是用模型标签数量
代替用户实际能读到的内容。

## 决策与边界

初步推荐 **PDFBox 保留既有文字串，Docling 提供离线区域候选，原页作为保底**。
PDFBox 绘制操作可以补充知识框外边界，但本轮纯 JVM 原型漏表格、拆散多行公式，
不能作为默认自动识别器。Docling 的候选边界也没有达到直接用于自动裁图的程度：
知识框外框、坐标轴标题、公式前缀仍有漏裁。进入产品前需要边界扩展与人工阅读顺序核验。

这是一项基于本轮数据的工程建议，尚未定案为所有 Windows 用户安装 Docling。
Windows 的实际新增体积、安装时间与速度没有测完；D 的同页远程模型比较没有执行。
在这些缺口补齐前，保留当前导入文字契约，不以 Docling 或 VLM 重写书中文字。

第二阶段显示必须等 TON-1667、TON-1670 的显示改动合并，并与 TON-1665 使用同一种
页资产模型；本次只增加实验工具和文档。没有改阅读器、导入模型或共享 UI 文件。

## 材料与方法

- 真实教材：同一本 620 页 PDF，选 20 个复杂物理页，SHA-256
  `43dc0c53b7a52fd074cafa7b05f324babaef4b6349dff2d8134a61971d971c04`。
- 页码固定为下表所列。覆盖知识/习题框、表格、多行公式、图像和并排图形；没有找到
  可作为双栏正文基准的页面，也没有单列足够的页边注样本。不能外推到所有教材。
- Mac 本机读取原页并逐页看 Original/B/C 三列边界覆盖图。原文、PDF、JSON、坐标、
  标注与图片全部留在本机私有目录；仓库只存通用工具、数字和结论。
- 一个知识框作为一个对象，框内公式不重复计数；多面板图逐面板计数；连续推导算一组，
  独立相邻公式分别计数。共人工数得 67 个对象。
- “完整候选”要求一个候选矩形完整包住对象、必要坐标标签、公式行/编号及知识框标题与
  外框。边界模糊或裁掉一部分时按失败计；没有量化多裁正文的代价，也没有金标准坐标集。
  这是人工边界筛查，**不是实际裁图嵌入后的保住率**，需要独立复核。
- 每页 A/B/C/D 的人工阅读顺序错误数均为 **未验证（null）**。Docling 的
  `single_column/conflict/unknown` 只是自动门禁，不能写成“阅读顺序零错误”。

“Docling 没在真实教材上跑过”的原始前提不成立：TON-1424 已留下 10 本、1011 页的
真实材料记录。本次仍重新跑固定 20 页，不沿用那次速度或候选数量冒充本轮结果。

A 的 0 是没有特殊块候选，不意味着普通文字读不出来。A/C 的差异 0 是构造保证，
不是原始文字提取准确率，也不是偏移回归测试结果。B 没有接入产品；其差异说明不能
直接替换既有文字串，不能解读为 32.3% 的识字错误率。

若把整页回退视为所有原页对象可见，B 的边界筛查会从 60/67 升到 62/67；仍有 5 个
漏裁对象所在页未触发回退。回退并没有在本轮实现于文字视图，也没有测阅读体验。
C 对裁剪操作、页/文字旋转、不同 CropBox/MediaBox、shading 仅发出回退标记；
仍展示候选用于诊断。没有实现表格线聚类和多栏检测，不代表纯 JVM 路线的最终上限。

D 与“真实教材只在本机读、原页不得上传”的本卡约束冲突，因此没有向 API 发送这批页。
不能把 D 的空白写成质量差或成本高，也不能用合成页替代同页比较。

## 具体反例与速度

- C 在 46/49/247/272/544 页只圈到表内数学符号行，整表漏掉；不能把命中数学字体
  等同于识别整表。184 页把连续公式拆成多个框。
- B 在 51/116/164/547 页没有完整包住知识框外边界；189 页部分公式前缀越界，
  298 页图形候选漏坐标标题。普通标签正确也不等于裁图边界正确。
- C 在 77/282/536 等页漏图形坐标标签，部分知识框标题/外框也在裁边之外。
  487 页大框虽然覆盖数个公式，也连带普通正文；“完整候选”指标没有惩罚这种多裁。

本轮 Mac 单进程、已有模型缓存，A 总 0.2077 秒，中位 0.00421 秒/页；B 总 16.5076 秒，
中位 0.60830 秒/页，最慢 2.82684 秒；C 在 A 之后增量总 0.1028 秒，中位 0.00363 秒/页。
另记 JVM 编译 0.2845 秒、A/C 进程总墙钟 0.5560 秒、B engine 构造 1.1573 秒。
首个 A 页 0.1132 秒、首个 B 页 2.7321 秒。没有测干净机器冷启动；不包括裁图栅格化、
嵌入 UI、模型安装或下载时间，不能直接视为用户翻页延迟。

## 产品实现契约与下一步

1. 保留现有 `BookPage.text` 和清理规则。侧挂 `TextSpan`、`SourceRegion` 或
   `StructuredBlock`；文本范围必须以既有页字符串的 UTF-16 为准。裁图不向文字串插入
   占位符、标题或 OCR 文本。零差异要靠合成 PDF 回归测试，不能靠原型宣称。
2. 与 TON-1665 对齐资产：书内容 hash、物理页、坐标系、源矩形、像素尺寸、可选说明；
   同一书页的插图和特殊块共用缓存与失效策略。当前只是契约建议，没有改其共享文件。
3. 候选必须扩展到外框、公式所有行、轴标题，再映射到已有文字范围。无法证明边界或
   阅读顺序时保留整页/原版入口，不将可疑片段静默删除。验证深色、缩放、块选字、分页
   和正文间距，按 `desktop-polish.md` 6.7/6.8。
4. EPUB/Word 当前的 `StructuredBookExtraction.kt` 仍将表格行连接成平文字，EPUB 的
   aside 还会被移除。后续从原结构生成侧挂块，同时保持既有页文字及偏移；MathML、
   Word `m:oMath`、表头/合并单元格与知识框样式要单独覆盖，不能只套 Markdown 表格。
   已有 `MathAsset` 可用于有可信原公式来源的块，无法核实的公式保留原图。
5. 先补人工阅读顺序逐页计数、真正双栏/页边注样本和 Windows 安装实跑；在本机材料
   边界内继续比较。显示前置合并后，实现块渲染，用同 20 页测真实阅读器保住率，
   再跑合成 PDF（知识框/表格/公式/双栏）文字不变测试和 winbox 真窗口验收。
