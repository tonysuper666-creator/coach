建议以 **Astra 的服务端与同步契约为骨架，合入 Opus 的产品细节、Sonnet 的盲复核**；三份都不能原样交给团队实现。以下已完整审阅三稿，包括 Astra 自稿。

引用简称：[O＝Opus](~/DeepTutor/design/round1-opus-full.md)、[S＝Sonnet](~/DeepTutor/design/round1-sonnet-full.md)、[A＝Astra](~/DeepTutor/design/round1-astra-full.md)；节号指对应设计。`DT`＝`~/DeepTutor/.venv/lib/python3.12/site-packages/deeptutor`；`SC`＝[brief](~/DeepTutor/design/brief.md) 指定的 StudyCoach 源码根目录。

**1．逐节对比**

| 节 | O / S / A 的立场 | 评审结论与理由 |
|---|---|---|
| 1 产品 | O：每KP一线程；S：主线与追问混排；A：学习、复习、随口问三类 | 采O屏幕状态＋S追问呈现；对象绑定清楚，且追问不打断主线。 |
| 2 规则 | O：加权通过、跨日构答稳固；S：三连对或一次构答通过；A：加权通过、严格证据可降级 | A证据边界较稳；O/S部分规则自相矛盾，阈值不能冒充学习效果结论。 |
| 3 账本 | O：服务端序号、证据投影；S：设备时间排序、证据事件；A：命令驱动、因果引用 | 采A信封＋O投影；S排序不能保证原因先于结果。 |
| 4 存储 | O：详细DDL、缓存；S：全量fold、fence；A：事务入队、不可变内容、fence | A最完整地覆盖异步任务与恢复；补O表约束。 |
| 5 AI | 都选服务端状态机；O异厂复核；S盲复核；A明确失败终态 | A传输契约＋S盲复核胜出；实际后端身份和失败语义是复核成立的前提。 |
| 6 协议 | O：命令＋消息快照；S：客户端上送事件；A：命令＋持久帧 | A更可靠：同ID异载荷拒绝、持久化ACK、未知状态事件阻止错误投影。 |
| 7 客户端 | O：现成SVG加载；S：自写SVG绘制；A：单文档WebView | 暂不裁定性能；优先验证A，O作对照。S承担最多自研渲染风险。 |
| 8 自适应 | O：宽高＋姿态；S：最小窗格算术；A：断点＋姿态 | 采S空间预算、O短高规则、A恢复要求；不能只按屏宽。 |
| 9 视觉 | O/S具体令牌与对比度；A强调语义、文字图标并用 | 合并；O/S更可施工，A补足非颜色辨识。 |
| 10 迁移 | O：细清单；S：题目关联及差异报告；A：暂存、原子发布 | A流程＋S映射＋O清单；数量相等不代表语义迁移正确。 |
| 11 验证 | O：详尽黄金例；S：故障注入；A：短答、时区、杀进程 | 合并，但先修规则矛盾，否则测试只会固定错误。 |
| 12 交付 | 都先风险验证、双端闭环，再扩展 | 采A纵向集成；三份M1均偏宽，应削减辅助功能。 |

**2．逐份关键缺陷**

严重度：**致命**＝按当前规格会产生错误成绩、错误完成或不可靠迁移；**重要**＝实现前必须补约定；**次要**＝局部修订。

**Opus**

- **致命｜§2、11规则不可能同时成立。**“复习能产生稳固”“稳固⇒已通过”“复习永不改变已通过”三者冲突。必须选择普通复习不升掌握，或明确允许复习中的独立测评升掌握。
- **致命｜§10活库读取错误。**对仍运行的DeepTutor使用`immutable=1`，会跳过锁与变化检测；它不是普通只读模式。应采用只读连接的一致性快照。依据：[SQLite URI说明](https://www.sqlite.org/uri.html)。
- **致命｜§5桥修补不够。**只增加身份、请求ID、推理强度，仍无法识别中途失败：现有桥捕获异常后继续发送默认`stop`与`[DONE]`，可能把残缺讲解记为完成。依据：[subscription_bridge.py:692](~/DeepTutor/tools/subscription_bridge.py:692)。
- **重要｜§3、4序号矛盾。**信封规定课程内连续序号，DDL却是全库`seq PRIMARY KEY`；多课程会冲突或出现课程游标“缺口”。
- **重要｜§4租约无fence。**租约到期后旧任务仍可能提交；单写者只能串行写库，不能判定任务已失权。
- **重要｜§5短答被拒。**复制“≥3词元、≥8字符”会拒绝“0”“无”等正确答案；中文词边界规则还可能拒绝句中片段。依据：`SC/packages/ai-runtime/src/grade-validation.ts`。
- **重要｜§10迁移规则不足。**文件hash变化会重新导入；旧通过又被送入新公式，不能保证原通过不掉级。需稳定源ID和显式`LegacyPassed`事实。
- **重要｜§4备份遗漏外置blob实体；§7草稿防抖300ms却承诺杀进程不丢最后输入；§8在1120dp塞入300＋380侧栏后，对话空间未设下限。**
- **次要｜§12“一个目录＋jar即可搬迁”漏了Python、Node、CLI和订阅登录依赖。**

**Sonnet**

- **致命｜§3设备时间排序破坏因果。**手机快几分钟，服务端评分可能排在答案之前；相差不足24小时不会触发修正。“最终排序一致”不等于业务正确。应以服务端提交序号折叠，设备时间只供日记展示。
- **致命｜§3幂等键跨设备碰撞。**`open:{kp}:{deviceSeq}`和override键缺deviceId，而数据库`idem`全局唯一；两设备相同局部序号会误去重。
- **重要｜§2、3规则未闭合。**“复用SC全部条件”包含阶段限制，却删除阶段且未定义替代；`Position`把已提交、尚未评分的题当“未答完”，容易诱发重复提交。依据：`SC/packages/domain/src/mastery-evidence-policy.ts`。
- **重要｜§2弱化稳固。**两次选择题也能稳固，缺构答证据；“新题”不等于独立迁移能力。一次构答即可通过，也是新政策，不能声称等价继承旧门槛。
- **重要｜§5仍继承短答门槛、桥错误终态。**“一次出题＋复核＋重出＋再复核”至少4次，与≤3次预算冲突；预生成尚未完成时也不能承诺零等待。
- **重要｜§5、6测验泄题边界不足。**ask不需租约且未规定答案暴露事件，用户可在待答题时索取提示而仍被算独立首答。
- **重要｜§7自写SVG子集未经证明。**固定48dp骨架替换为任意高度公式必然可能改变布局；中文字体、变换和基线都尚未验证。
- **重要｜§10把历史评分导为`exact`制造错误来源；日志主要被用于课程信息，却未明确保留历史日记。**
- **次要｜§12用“FTS手写SQL/换ORM”作缺少FTS5扩展的退路不成立：SQL写法不能补数据库引擎能力。**

**Astra，包括自稿**

- **重要｜§3、6缺业务唯一约束。**命令幂等不能阻止两设备用不同命令提交同一首答；测试提出“最多一次”，存储却未落实。
- **重要｜§3、6答案私有边界未闭合。**`AssessmentIssued`含答案hash，另有通用blob读取接口。若直接同步低熵答案hash或允许按hash读私有blob，会泄露测验答案；必须区分服务端账本载荷与客户端投影。
- **重要｜§2、3课程版本与规则版本含混。**对象绑定课程版本，却没定义升级后线程、位置、证据如何继承；`fold(events,ruleVersion)`又与“历史按事件版本解释”存在歧义。
- **重要｜§5没有把复核前状态持久化规格写全。**只有`GradeCommitted`，无法完整表达待复核、争议、恢复中的作业及用户查看原批改。
- **重要｜§7混合视图交互未设计。**正文在文档视图、题卡在原生层，缺插入位置、统一滚动、焦点与无障碍顺序；不是选定WebView就解决。
- **重要｜§10“源ID＋内容hash”只保证相同输入去重；源记录修改后可能新增第二份学习事实，缺替代关系。**
- **重要｜§2题族ID没有生成与复核规则；§3字符区间没有指定UTF-16/Unicode及归一化约定。**
- **次要｜§12保留阶段视图却没有明确M1是否实现，范围容易悄悄膨胀。**

**3．共识：可直接采纳的决定**

- KMP/Compose＋Ktor、共享纯领域逻辑、一本学习账本；避免跨端规则漂移。
- 对话自动绑定学习对象；追问不自动涨掌握，前置依赖不硬挡阅读。
- 服务端编排、冻结rubric、精确选择题判分、独立复核、真实失败提示。
- 通过与稳固分层；旧通过保留来源，不伪造严格证据。
- M1必须包含离线存答、四形态和真实AI验收；Windows后置。

这些共识没有解决阈值、复习升掌握或渲染实现。

**4．分歧：待团队裁决**

- **通过规则：**O/A近期加权；S三连对或一次构答。倾向保留加权规则，减少行为突变；迁移通过另存事实。旧算法见`DT/learning/mastery.py`。
- **稳固与复习：**O允许复习升稳固，S/A禁止。倾向普通复习仅调度，另设明确发起的“独立测评”，避免同一操作两套含义。
- **稳固资格：**S允许纯选择题，O/A要求构答。倾向后者，课程含论述与计算，猜对不能覆盖表达能力。
- **阶段：**O/S删除，A保留计划视图。倾向M1不建阶段机，M2再加，证据资格独立。
- **渲染：**O/S原生SVG，A浏览器。倾向先验证A与O；不提前承诺自写SVG绘制。
- **今天主动作：**O固定续接，S/A可能被复习替换。倾向未完成任务优先；复习作次卡，避免用户位置被算法移动。

**5．三者共同遗漏或覆盖不足**

- **跨库迁移一致性：**SQLite、JSON、课程文件并非同一事务；需导出清单、各源版本与二次校验，源变化则重试相关部分。
- **崩溃恢复：**调用已付费但结果未提交、提交成功但ACK丢失、取消与完成竞争，都需唯一终态和可恢复作业。
- **完整Markdown依赖：**三稿均假设封口块永不变化；后置链接定义可影响前文。应限定支持语法或重解析受影响块。依据：[CommonMark §4.7](https://spec.commonmark.org/0.31.2/#link-reference-definitions)。
- **恢复包完整性：**数据库、内容blob、规则版本、迁移映射必须一并恢复；hash清单本身不是文件备份。
- **共享额度：**独立桥进程的并发信号量不会自动与DeepTutor协调；需共享调度或限制后台并发。
- **证据纠错：**申诉、错题键修正、材料修订后，哪些历史评分重算、哪些仅标失效，需要用户可理解的规则。

**6．整合建议与M1**

按节开工：**①O＋S**，统一续接；**②A＋O**，先修证据冲突；**③A＋O**，固定服务端seq；**④A＋S**，补唯一约束与完整备份；**⑤A＋S**，明确终态和盲复核；**⑥A**，补私有载荷过滤；**⑦A/O实测择一**；**⑧S＋O＋A**；**⑨O/S＋A语义状态**；**⑩A流程＋S映射＋O清单**；**⑪三者合并反例**；**⑫A纵向交付**。

必须补入契约：

```text
UNIQUE(actorId, commandId) + payloadHash
UNIQUE(assessmentId, firstSubmissionSlot)
提交评分须匹配 questionVersion、answerHash、leaseFence
job终态 = completed | failed | cancelled，互斥
sourceId稳定；sourceHash变化产生revision，不再新增首答
```

**建议的M1范围：**单课程ECNM10119；Mac＋Android；今天、路线、学习、复习、记录、基础资料六屏；讲解/追问、选择题/构答、可信批改、双层证据、统一复习、事实日记与人工区；引用可打开原文；迁移与证据下钻；缓存阅读、离线存答、四形态。

暂不做全套九讲法、阶段机、模考、随口问自动生成复习卡、多课程导入UI、Windows、通知。连续7天真实学习验收，不能用自动化跑通替代。

**必须先做的3个spike：**

1. **双端富文本安装包。**A与O渲染路径比较50条课程公式及真实长回答；包含中文、表格、跨块引用、200%字号、四形态和IME。判定：无错式/丢字/遮挡，阅读锚点漂移≤一行；源码降级必须单独计失败，不能算渲染成功。
2. **真实AI到可信成绩。**真实桥跑讲解、出题、批改、盲复核；注入错键、伪引文、中途断流和取消。判定：错误不提交掌握，实际后端可核对，取消后所属进程组退出；报告正文首字p50/p95及未判率。
3. **迁移＋账本＋故障恢复。**49点/108题逐项对账，重复及增量导入；双设备抢答、时钟偏差、断网重传、服务端崩溃、备份恢复。判定：零丢答、零重复首答，旧通过不掉级，恢复后投影一致。
