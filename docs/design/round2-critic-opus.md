# Coach 第二轮交叉评审（Claude Opus 5.5）

三份全文都读完了（三份都在），我自己那份按同样标准挑毛病。【实核】＝本轮只读核对过，对象：桥 `~/DeepTutor/tools/subscription_bridge.py`、`DT/learning/mastery.py`、SC 的 `grade-validation.ts`/`review-queue.ts`/`math-markdown-policy.ts`、题库 JSON、`chat_history.db`、课程库、`bridge.log`、`~/.gradle`。缩写同第一轮：`DT/`＝DeepTutor 站点包，`SC/`＝StudyCoach 只读源码。

**结论**：三份骨架几乎一样（服务端状态机、不用 tool-calling、共享 KMP 领域层、两层掌握、单写者 SQLite），差别在能不能直接开工。
- **Opus** 最完整，但超长，且有三条规则叠在一起会把学习卡死。
- **Sonnet** 最精炼，几处判断最准（盲复核、题库键没人核过、工具链实况），但按设备时钟排事件是硬伤。
- **Astra** 对桥的判断最准，但渲染方案有漏洞，可开工程度最低。

建议以 Opus 为底稿，按 §6 逐项替换。

## 2. 各份的缺陷

### Opus（我自己写的）
1. **重要｜三条规则叠在一起，会重现 10-28“答多少遍都过不了”。**
   - 规则一：沿用 DT 的 5 次加权窗（`DT/learning/mastery.py` L17–37）。答错一次后，要再连对 **5 道新题**才过（`[错,对,对,对,对]`＝0.875）。
   - 规则二：带提示的作答按半分。带一次提示后，要再连对 3 道。
   - 规则三：“有待答题时导师每次回复都算提示”。他问一句澄清，就触发规则二。
   - 同时 14 天内不许重复用题，而题池每个知识点只备 2 道选择题＋1 道构答题。
   - 结果：我在赌注 3 里写的证伪信号，第一周就会出现。
2. **重要｜没复核过的题也能算进“已通过”。** `passContribution` 只看批改状态，不看 `keyState`，选择题判成 `EXACT` 就直接计分。而这 108 道题是模型写的（改造记录 §五“108 道原创练习题”，`tools/practice_questions.py --model claude-sonnet-5-5`），答案键从没被独立核对过。文中“未复核的题只用于 practice”也自相矛盾：practice 本来就算进已通过。
3. **重要｜检测不到截断。** 桥在已经出字之后，不论是超时还是异常，都照常发 `finish_reason:"stop"` 和 `[DONE]`（`subscription_bridge.py` L429–434、L723–737）【实核】。我列的三处桥改动里没有“终态”这一项，所以 `TRUNCATED` 根本判断不出来，截断的讲解会被记成 `explanation_delivered`。
4. 次要｜离线包下载时就写 `question_posed`，而 Position 的 `pending` 取“没有答案的 posed”→「继续」被包题劫持，没答的包题永远挂着。
5. 次要｜复核方看得到答案键，有确认偏差，不如盲复核。
6. 次要｜桥副本的 `LOG_FILE`、`CLAUDE_CWD`、`AGY_BIN` 都指向 `~/DeepTutor`（L24–30），且要用 DT 的 venv（fastapi/uvicorn），不改路径就会往 DeepTutor 运行目录里写；两份桥各有信号量，Claude 实际可并发 6 个。
7. 次要｜工具链写错：`~/.gradle` 已有 15GB，含 wrapper 8.11.1/9.5.0、Compose desktop 1.12.1、Kotlin 2.4.x、coil3、jetbrains markdown【实核】，不需要“首次下载 1–2GB”。
8. 次要｜绑定写死 Tailscale IP，开机时 Tailscale 未就绪就会失败；应用 MagicDNS 名并重试。
9. 次要｜正文约 1.05 万汉字，超出 6500 字上限约 60%。

### Sonnet
1. **重要｜按设备时钟折叠事件。** 排序键是 `(at, deviceId, deviceSeq)`，设备时间偏差在 24 小时内照单全收。手机慢 3 分钟，作答就会排到服务器的 QuestionIssued 之前。晚到的离线首答还会改写“首次作答”和“最近 3 次”的结果，导航可能被事后改掉。
2. **重要｜“稳固”不一定意味着“已通过”。** 已通过看最近 3 次，稳固看两条合格证据，两者数据来源不同；再加上单选题“未见变体”也能算稳固，就会出现“稳固但未通过”的状态。另外选择题路径的已通过可以撤销，简答路径通过一次就永久有效，口径不一致。
3. **重要｜同样检测不到截断**（同 Opus-3）。另外它 M0–M1 直接连 DeepTutor 正在用的 8790 端口，又说改动加在“副本”上，前后矛盾。
4. 次要｜Compose 的 `PlaceholderVerticalAlign` 只有 7 个固定选项，不能按任意基线偏移。它写的“baseline(em) 对齐”需要靠给 SVG 补边来实现。
5. 次要｜跨厂商兜底要用户显式同意，但没定默认值。默认不同意的话，Claude 一出故障，导师就全停了。
6. 次要｜“问另一位导师”可以点 Grok，但桥里没注册 Grok（L44–49）【实核】。

### Astra
1. **重要｜渲染方案覆盖不全。** 它的设定是“文档视图只承载 Markdown 和公式，题目按钮用原生”。那么生成题的选项、批改卡、日记里的公式，在原生控件里就显示不出来。桌面的 KCEF 要通过 SwingPanel 嵌入，Compose 的弹层盖不住这种重量级组件【待核实】；首次启动还要下载 Chromium。
2. **重要｜迁移只做一次。** M1 最早 11 月底才能用，11 月他仍在 DeepTutor 上作答，迁移必须可重复、可增量。
3. **重要｜细节不够，团队拿到还得再设计一轮。** 事件只写到“族”，没有逐条的字段和幂等键；SQL 只有表名；投影没有精确定义；断点规则只按宽度给。
4. 次要｜把阶段保留成“计划视图”，带 PhaseChanged 事件和“覆盖≥80% 推荐模考”规则，违背“不要治理过重”。`courseVersionId` 又把 SC 的版本机制带了回来。
5. 次要｜“讲解 60 秒”若是总时长，长讲解会被截断（日志里 1167 字的回答已用 30.9 秒【实核】）。
6. 次要｜扫码配对要相机权限和二维码库，6 位码更省事。

## 3. 共识（可以直接采纳）
- **AI 编排**：服务端结构化状态机，不用 tool-calling。只有两类调用：流式纯文本、JSON 非流式。
- **领域与账本**：领域层用 KMP 共享，客户端在本地算投影。SQLite 用 WAL 模式、单一写入者。对话正文不进账本，账本只记学习事实。
- **同步**：离线发件箱，命令 ID 在设备上生成，保证幂等。
- **认证**：配对码换 256 位令牌，服务端只存哈希。
- **答案与批改**：标准答案永远不进导师上下文。rubric 冻结、逐字证据、跨厂商复核；复核不成，就不写掌握。
- **学习规则**：迁移来的旧通过只算“已通过”，不算“稳固”。证据资格看活动的 purpose，不看阶段。前置依赖软锁。复习合成一个队列，只改日程。时间本身不推进任何状态。
- **设计**：标题打包中文衬线字体子集，正文用系统无衬线；tertiary 色不用于承载信息。
- **节奏**：不承诺期中前可用；渲染是 M0 的第一风险。

## 5. 三份都漏掉的
1. **`$` 既是货币符号又是公式定界符。** 课程库里有 47 个文件、332 行，题库里有 11 道题干，同一行出现两处 `$数字`（如 “$14 trillion … $2.3 trillion”）【实核】。三份都打算移植的 `SC/packages/domain/src/math-markdown-policy.ts` 把 `$…$` 一律当公式（L105），没有处理货币的规则，S-A 的语料一跑就会乱。对策有三条：
   - 提示词要求模型写公式只用 `\(\)` 和 `\[\]`；
   - 规范化时，`$` 后面紧跟数字的一律按货币转义；
   - 导入题库和资料时做同样的处理。
2. **题目供给不够。** 每个知识点要≥3 道“新题”的首答。答错一次，还要再来 3 道（按 D5）或 5 道（按 DT 的窗）。49 个知识点第一次铺满题池，约需 150 次物理调用（生成＋盲复核）。按 Opus 定的后台每天 60 次上限，要 2–3 天；而且偏偏在他答不上来的时候，题池最先见底。
3. **手机离线时选择题没有即时反馈。** 三份都不把答案键放上设备，离线答题要等 Mac 上线才知对错。单用户应用要防的是“先看到答案”，不是作弊：离线包可带答案键（加密存库、不显示），本地提交锁定后再揭晓，同步后以服务器重判为准。
4. **三个常驻进程的托管。** Ktor（JVM）、桥副本（Python，DT 的 venv）、mathsvc（Node）：启动顺序、健康检查、launchd、日志位置都没写。
5. **切换与回退计划。** 何时停用 DeepTutor（不在考前 7 天内切）、切换前跑几次增量迁移、切换后两周内能否退回。
6. **开发期额度。** Multica 团队、Coach 的 live 测试与后台出题、他本人学习共用同一组订阅，需要按周分配并记录。
7. **逐字证据的阈值没考虑作答语言。** SC 的“≥3 个词元、≥8 个有效字符”（`grade-validation.ts` L12–13）是按英文定的。他用中文答“逆向选择”只有 4 个字，过不了；计算题答“0.25”也过不了（Astra 只提了后一种）。
