# Windows 学习数据同步与换机恢复

**TON-1892 · 待实现的协议。** 点保存即写入本机，关闭应用或断网不影响这次保存。只有 Hermes 确认持久化以后，这次修改才有异机副本。两台 Windows 设备共用一个 Sable 账号时，各自的离线工作都能进入备份。书的原件、处理结果和书架权限由 TON-1894 提供。产品分工见 [产品决定第 16 条](../PRODUCT_DECISIONS.md)。

## 从哪些数据恢复

盘点基线为 `8cb879c9`。下表的大小是 SQLite 合成样本的增量 KiB。每张代表表单独建在空的内存库中，写 256 行，按写入前后页数差乘 4096 B 计，包含主键索引。使用仓库建表语句，保留列默认值及空值，必填文本用 64 个 ASCII 字符，枚举用短值，整数用行号。没有计外部索引、WAL 和书本文件。真实问答和试卷的长度可变，迁移时另报每表行数和规范化内容字节总和。

## 稳定 ID 与迁移

### 旧库归哪个账号

以同一旧数据目录的 `library.sqlite` 和 `exams.sqlite` 为迁移单位。开启学习同步后，在首次迁移的写锁内取得当前已认证的 Sable 账号 X、该目录所用过的已验证 Sable 身份集合，以及所有书的非空 `books.import_account_key` 去重集合。登录身份按服务器返回的稳定账号键去重；临时 session key 只按已保存的 `book_upload_account_bindings` 映射解析。无法解析的非空键按归属未定处理。卷的 `owner='learner'` 仅用来筛选学习者作答，不能证明归属。

| 已有证据 | 对八类旧数据的动作 |
|---|---|
| 已登录 X，目录仅有 X 一个已验证身份，所有书键为空或解析为 X | 自动把两个库的八类学习数据整体绑定到 X，包括无书键的课程、考点、掌握度、模考卷及学习者作答。即使每本书的键都为空也执行。把绑定和迁移批次持久化，完成校验后用 X 的队列上传。 |
| 登录记录出现第二个账号、任一书键指向其他账号，或有未解析的非空键 | 保持旧库可读，两个库均不入上传队列。展示已知归属和待认领项的分类条数。用户登录目标账号，选中可归其所有的书、课程或独立卷及关联学习数据，确认后才在本地事务记录所选条目和账号。明确属于别人的条目不能改派；含跨账号引用的组保持待处理，取消选择不写绑定。 |
| 尚未登录 Sable 或只有设备配对 | 继续本机读写；在取得 Sable 身份后重新判定。 |

恢复未完成迁移时重用已保存的绑定，重新核验会话和源库书键，出现新冲突就暂停该批次。切换账号先取消旧传输、关闭旧账号目录，再打开新目录；回包校验会话代次。所有权已确定的旧记录不会因再次登录而重新认领。

### 八类数据的记录键

引用为当前账号范围内的 `(kind, recordId)`。下表给出**所有迁移来源**，同时是 TON-1891 的引用契约。每个源表占一行，首项固定为 kind，后续项从左至右取原库列值。书字段使用原文件 SHA-256 小写十六进制；`books.id` 就是这个值。模考卷按旧库的冻结身份 `(book,paper_id)` 引用，导入时校验 `paper_hash`；同键异卷保全两份并报告冲突，再给另一卷分配新 paper_id、重连对应的作答。其他可变内容、排序和设备身份均不参与自然键。

* **编码。** 使用 UUIDv5，命名空间 `8de10572-23e3-43ea-bdb0-b45b39375efa`。名称为无 BOM 的 UTF-8 紧凑 JSON 数组。主键整数用无前导零的十进制字符串。文本保持原大小写和码点；双引号、反斜杠以及退格、制表、换行、换页、回车按 JSON 短转义，其余 U+0000–001F 用小写四位十六进制转义，其他字符原样编码。高亮的 `version` 在 v8 取书散列。例：同一题分别以 `["answer",书,课,模式]`、`["mistake",书,课,模式]` 和 `["card",书,课,模式]` 生成三个 ID。
* **两个旧自增表。** `id` 保留同库内内容相同的多次操作；为区分两个旧库内恰好同号但内容不同的事实，再取不可变事实的摘要。摘要为下列有序数组按上述 JSON 编码后的 SHA-256 小写十六进制。整数同样转为字符串，SQL NULL 写作 JSON null，内嵌 JSON 文本按库存字符串编码。字段全部取自迁移前的行。

  * main 的 v9 增加了可重试的问题。对已有非空 `write_id` 的行，用下列固定数组计算 `turnDigest`：常量 `question-v9`、`thread_id, selection_id, question_text, created_at`。外层仍是 `ask_turn, book, id, turnDigest`。写入片段、失败、重试和完成始终更新这一个问题。保留回答、出处和状态；新机把未完成轮次作为可重试问题恢复，并生成本机写入令牌。两台机器分别取得的不同回答按并发文字处理。原 v8 行升级到 v9 后 `write_id` 为空，继续使用上一行的 v8 规则。
  * `historyDigest` 依次取 `lesson, mode, kind, text, revealed, understood, guessed, answered_day`。
  * 相同旧库的两份拷贝即使分别首次升级，也会为同一条事实生成同一个 ID。若两个独立旧库连旧行号和所有事实字段都相同，v8 无来源信息可区分，按一条历史事实恢复，保留两份迁移备份供核对。升级后新增的轮次和作答事件在创建事务中取得 UUIDv4 并持久化；恢复或再导出直接沿用这个 ID。其余行一律按表中自然键派生，新增业务对象的原生 id 在首次保存时固化。
* **迁移与恢复共用映射。** 为每行保存原键、kind 和 recordId。还原到新机时恢复映射，旧自增主键在目标库可重新分配。重传同一基线按账号、kind、recordId 和业务内容去重；设备 ID、迁移时刻和本地自增序列不能制造第二个版本或再次计分。业务内容确有差异才按后文的并发规则合并。

固定样例可供迁移器和导出器交叉验证。书键为连续 64 个小写 `a`、lesson 为 `L1`、mode 为 `CHOICE` 时，`answer` 应得 `e3567cb8-d31b-579c-85f6-495d6f9b3ac1`，`mistake` 应得 `239c9f9f-8edd-5de1-9742-3d4d7cb3dfc9`，`card` 应得 `c2dd5e69-a37a-58d7-bc1f-e2bab35f1ff3`。

### 何时切换

每个源库新增记录映射及操作队列。记录含创建/修改 UTC 毫秒、最后写入设备、因果版本及可空删除时间。原始已知时间照搬，旧行时间缺失用迁移时刻并记 `timeSource=migration`，学习日期仍可为空。保留 `book_notes.revision` 与 `last_mutation_id` 支持编辑器本地乐观锁。旧表、字段、接口本阶段删除清单为空。

停写后先用 SQLite 一致性备份保留两个原库，分别事务建映射、索引、基线队列及完成标记。新写与排队在源库同一事务内完成；两个库均已提交、当前会话仍与绑定相符，才允许发送。崩溃后只重跑未完成的事务。旧已删除批注种下墓碑。比较升级前后逐类主键、条数和业务字段摘要并跑 foreign_key_check、integrity_check；全部通过才切换到新目录。失败继续从旧副本读，保留未上传编辑。

## 写入、重传与拉取

Windows 正式包通过已有的 `-Pcoach.release=true` 将 `-Dcoach.learningSync=true` 写入启动配置，安装后默认同步。开发运行默认关闭；客户端可用 `COACH_LEARNING_SYNC=1` 或 `0` 覆盖启动配置。服务端独立使用 `COACH_LEARNING_SYNC=1` 启用接口。开关关掉期间也可本地编辑；已建基线的库继续记变更，初次启用扫描当前行及已有墓碑。每个源库一个持久写流，服务器从已认证设备绑定取得 deviceId；同设备两库用不同 streamId。每次本地事务取流内递增计数，`opId=(streamId,counter)`；不同窗口共享 SQLite 写锁。一个事务可在一个操作内含多条有依赖的行。网络层复用现有退避、唤醒及单飞机制，学习操作留在业务库，避免写完书库、还没写另一文件的 outbox 就断电。

| 接口（相对路径） | 约定 |
|---|---|
| POST `/learning-sync/push` | 发送协议版本 1、epoch、流、计数、规范化内容摘要、操作数组。每项含 kind、recordId、动作、被修改字段、这些字段已见的版本标识，及时间；删除无正文。客户端按流顺序发送。服务端在一次事务内校验引用、合并、登记回执和账号内递增 seq，持久化后确认。已接收的重复操作不再执行，同 ID 不同摘要报冲突，计数缺口要求从首个缺失值重发。 |
| GET `/learning-sync/changes` | 使用账号、epoch 绑定的不可跨用分页游标；返回有序变更、墓碑、下一游标及高水位。应用远端操作、推进本库游标同事务，不产生二次上传。书库和考卷库分别追到同一水位后才确认设备进度；跨文件引用未到先暂存。 |
| GET `/learning-sync/snapshot` | 新机或游标过期时按固定 seq 枚举一致性快照（含字段版本和流确认位置），各页绑定同一账号、epoch、水位。快照租约过期整次重取。先写临时库，校验计数与摘要并应用其后的增量，成功后切换。期间本地写操作要冻结切换或重放。旧机全量重取前单独保全待发操作及其原始因果上下文。 |

服务端以账号为界串行提交；seq 只用于传输次序。对每个可变字段保留当前未被覆盖的操作 ID。编辑只替换作者实际见过的版本；本机未确认改动作为本地覆盖层，拉取不会覆盖正在编辑的文字。并发标量按 `(Lamport,streamId,counter)` 字典序取最大，Lamport 在观察远端后递增，时钟拨快不会改变胜负。回执丢失重发原字节。限批按编码字节和项数分包；单个大试卷或问答分块暂存，校验整件摘要后同事务发布，过期临时块回收。

Windows 以 UTF-8 字节切分超过 256 KiB 的操作。每次开始或重连时，先向 push 提交原操作的流、计数、长度与 SHA-256。服务端返回已持久化的下一字节偏移，或已提交操作的回执。随后每次最多发送 256 KiB 原始数据，以 Base64 装入请求。最后一块通过整件摘要校验后，服务端在同一事务中合并记录、写回执并清理暂存块。单个序列化操作（含修改前后两份数据）的上限为 64 MiB，每账号未完成上传共用 256 MiB 暂存空间。

增量与固定水位快照支持 `chunks=1`。大正文在页中以长度和 SHA-256 表示，客户端以该记录的 seq、账号代次、传输代次及可选快照令牌向 `GET /learning-sync/chunk` 按偏移取块。收齐并校验后才应用原页、推进游标，或累入快照摘要。下载前缀保存在本机源库。上传前缀保存在账号目录的 `learning-parts.sqlite`，独立于正式学习库备份。中断超过 24 小时的暂存数据在随后访问时回收。

书及课程父项先在临时库建最小目录记录，保持原 ID；书的原件未下载时可查看学习记录，原件到齐再按散列重连定位。一次跨页快照未完成时继续保留原活动库。恢复完成同时核对学习快照水位和已授权课程账本的追赶结果。

## 两台电脑同时改一条时

| 数据 | 因果相继的修改 | 独立离线修改 |
|---|---|---|
| 当前页、书签、章节进度 | 跟随新位置，回看前页也能保存 | 页与偏移是一组标量；停留页集合取并集，手动标记优先于推断，两个手动选择按标量规则。书签按 ID 合并 |
| 批注、草稿、高亮 | 编辑覆盖已读版本；删除结束本轮记录 | 不同字段的修改合并，同一段文字保留各个并发版本，按操作 ID 稳定排序。手动合稿引用全部父版本。高亮按锚点身份去重。删除时只抢救删除者未见过的用户手写文字，见下节。 |
| 书内问答、错题及作答 | 已完成的 turn 和作答是不可变事实，新提交有新 ID | 取事实 ID 并集，同一操作只计一次。同一题的独立错误都保留，重建当前错题状态；已保存的问题、答案、出处保持配套。同题未提交的文字按批注规则保留 |
| FSRS 与掌握度 | 升级时为每张卡和概念固化状态与已包含的证据边界。新评分记录 rating、学习日、算法版本及参数；新证据使用稳定 event ID | 在共同基线上将新增事实去重，按学习日、因果序号、流与计数重算；原历史已在基线内的只作展示。合并首次独立导入的基线时保留两份原始状态，选有较晚可证复习日期的一份（同日按稳定 ID）为起点，不重复累计旧历史。以领域 FSRS 和 mastery 算法重放，禁止逐列取最大值拼出一张卡 |
| 课程、考点、概念、材料和本地模考 | 逐字段更新，来源/材料按关系 ID 增删；卷内容由冻结 hash 验证 | 显式锁定的编辑优先于自动刷新；并发标题等标量固定择一，手写说明按批注规则。试卷按版本并存，作答按 attempt ID 合并；并发交卷各保留冻结答案及对应成绩。冲突的活动卷选一份恢复计时，另一份作可恢复草稿，避免违反单活动卷索引 |

同一书或课程删除时也记录依赖关系的删除，恢复端按父子关系应用。普通更新不得隐式创建缺失的父项；并发手写内容可保存在账号内独立的恢复条目中，并保留原定位。

Windows 保留一份当前草稿。若另一端改过的文字在合并后被覆盖，服务端在同一事务中写入 `draft_version`，与当前记录一起经增量或快照下发。固定键的输入顺序为 `[draft_version, 原记录 ID, 原轮次, 编辑者的 (Lamport, stream, counter), 题目槽位]`；单段草稿用空槽位。删除与未见过的手写修改并发时，恢复条目沿用原轮次，原草稿保持删除。

本机 `learning_draft_versions` 保存未发问题、简答文字、章节练习各题的手写答案和考点练习文字。副本带书、页或题目定位。有来源书的副本可在该书笔记页的「问答」中查阅并导出全文。没有来源书的考点草稿按考点 ID 保存在本机，课程编辑器的版本选择入口后续接入。

## 墓碑、账号和备份

### 同一条记录删除后再建

固定键标识“哪条记录”。另在 `sync_records` 保存该键已结束的最高轮次，初始为 0。第一轮为 1。每个创建、编辑、删除都在本地事务中固定目标轮次；子记录同时记录所属父项的轮次。删除第 n 轮只结束该轮。再添加书签、重新划高亮、重填草稿或导入同一散列的书，仍引用原 recordId。push 携带创建时已见的删除操作 ID，或快照中该键已结束轮次的凭据；changes 和 snapshot 都下发对应信息。

| 用户动作 | 两端收敛后的结果 |
|---|---|
| 已看到第 n 轮删除，又主动创建同键 | 凭已见的删除创建第 n+1 轮，两台机器同时这样创建也只产生一轮，字段按本类型合并。本机离线先删再建，按 outbox 原顺序提交。 |
| A 删除，B 在未看到删除时编辑第 n 轮 | 第 n 轮结束。若 B 改的是批注正文、草稿或手写说明，按原键、原轮次和编辑 opId 生成一份私有恢复副本，只保留这次手写改动和定位。书签标记、高亮范围、阅读位置、章节进度和复习卡状态按删除处理，副本数为零；书签另附的手写备注只保全改过的文字。 |
| 第 n+1 轮已存在，又收到旧编辑、重复删除或旧创建 | 只按操作原有轮次处理；旧删除不能结束新轮，旧操作不能写进新轮。先到编辑后到删除时，按删除所见的字段版本作同样判断；即使新轮已经创建，两种到达顺序也得到相同的手写副本。 |
| 删书后重导同一文件 | 新书沿用原散列，父项进入新轮；在此次导入下创建的子项绑定新父轮，可正常重建书签、进度、错题和 FSRS 卡。来自旧父轮的子项或延迟级联删除只作用于旧父轮。 |

墓碑及对应的删除变更至少保留 **90 天**，被删除的业务正文可立即清除。所有活跃设备都确认越过删除 seq 才能压缩；超过 90 天未确认的设备写租约失效。压缩后在同一账号的 `sync_records` 仅留键、父轮次、最高已结束轮次和删除标识，不留学习正文，直至删号。新机快照包含这份最小信息。收到旧租约请求先要求拉快照；恢复旧队列时保留入队时的原始因果上下文和轮次，只更换传输租约。补传前先按原操作身份及已确认计数去重。设备在快照后主动创建才使用快照提供的删除凭据。

Hermes 复用经鉴权的 `UnifiedBookScope.fromCall` 推导账号。设备注册、读取单条、变更、快照、分块和回执均先取得同一范围。客户端体内的 owner、书散列、游标、设备号都不能改变范围。关联书籍的恢复可在本账号暂存，下载或读取原件必须再检查本账号书架。共享处理结果不得写入私有学习内容。匿名访问返回 401；外账号 ID 与不存在的 ID 返回同一结果。应用日志仅留类别、条数、失败码。

**每账号一份学习 SQLite 文件及独立备份目录**，路径取服务器解析出的规范范围。新增表为 `sync_meta`（epoch、水位）、`sync_records`（状态、字段版本和墓碑）、`sync_changes`、`sync_receipts`、`sync_streams`、`sync_devices`、`sync_chunks`。同名本地 client meta 不在该文件。学习快照沿用 `LedgerStore.backup` 的 SQLite 一致性复制及完成标记做法；现有 coach.sqlite 的水位不能代表此文件。每个完成副本记账号代次、seq、分表计数及摘要。以校验成功的新副本推进学习备份水位，再裁客户端已确认操作。正常恢复使用最新完整副本，隔离目录校验后换新 epoch，客户端保有的较新操作按原身份补传。回滚到更老副本可能缺中间操作，需先从较新完整副本或保留日志补齐并核对水位，不能将落后状态发布为恢复成功。

### 删号及重新注册

服务端以不可变的 `(scopeKey, accountGeneration)` 定位一次删号。Sable 的 `scopeKey = sable-<sha256(sub)>` 在重新注册后相同。选择**清完旧代次才允许重新注册**，适用于所有按 scopeKey、friendId 或设备索引的旧存储。账号注册表独立于业务备份。先原子地把活动代次 g 切为「删除中」，记录作业和经过认证的 friendName、friendId、设备清单；封住登录换票、后台写入、同步和备份，吊销旧凭据，等待在途请求、Bridge 结算及备份任务退出。停用一个设备或一次鉴权失败不能启动删号。

作业每次处理存储前，在同一账号独占锁内核实「删除中、代次 g、作业 ID」再执行。锁覆盖每次外部文件修改直至返回；重启从已确认步骤续办。任何步骤失败都保留删除中状态，不能签发新代次。所有步骤结束并排空旧作业后才提交「g 已删除」；重新注册签发更大的代次。重复或迟到的 g 作业发现当前代次已变便直接结束。后台工作、快照、回执及恢复发布也校验代次。完成后注册表只留范围的不可逆标识和已撤销代次，不留姓名、设备清单、凭据或正文。

| 存储 | g 代次的清理及完成依据 |
|---|---|
| 学习同步库 | 删除上列七张表的整份账号库，包括最小删除标记、SQLite WAL/SHM、暂存块、快照、导出、完整和中断备份。按该代次清单核对均已移除。 |
| 书和处理结果 | 调用 TON-1894 的账号删除流程，移除私有书架、原件引用及账号目录；最后一个引用消失才回收共享文件。核对其他账号的引用仍可用。 |
| `friends/<friendId>/explanations.sqlite`、`requests.log` | 用服务端 friendId 定位，释放该账号缓存及句柄，删除讲解表（含 answer 原文）、数据库边车、请求日志及同目录 imports。核对目录消失，迟到的记录回调不能重建。 |
| `state/api-credit-ledger.json` | 与 Bridge 共用账本锁；停止该账号的新预留、结清或按现有保守规则记入未决成本，再原子移除 `friends[friendId]` 的逐日、逐设备用量和预留明细。保留不含身份的全局已花费汇总，赠额守卫不因删号而回退。 |
| `friends.json` | 与配置写入串行，只移除 `friends[friendId]` 单独配置，原子替换并回读；保留默认配置和其他账号。 |
| `*-sable-credentials` 与会话 | 当前 `SableVault` 在此目录保存全服务共享的 `grant.key`，实际的每设备密封会话在下行的 `sable_grants`。保留共享密钥；清除该账号会话及 `SableSessions` 的设备验证缓存。 |
| `coach.sqlite` | 在同一事务中按已冻结的设备及 friendName 删除 `sable_grants`、该账号的 `pairing_code`、`devices`（含 token_sha256）及 `sable_friends`。核对授权和账号元数据行归零；仅标记设备 revoked 不能完成这一步。数据库日志和备份纳入下一行。 |
| Hermes 主机及应用备份 | 清点覆盖以上目录、共享库、配置和账本的快照、轮转副本及异地副本。逐项删除该账号副本，或把其他账号的有效数据写入干净的新备份并退役原件；不可改的介质须等原副本到期销毁或完成该代次专用密钥销毁才能报清理完成。每份备份记录账号代次，旧无代次备份须能从冻结清单确认归属。恢复只在隔离目录进行，剔除已撤销代次后校验；无法区分代次的账号条目不得发布。主会话核对真实备份清单。 |

**Windows 收到经认证的删号结果时**，先按本机绑定核对 scopeKey 和 g，停止该代次的同步；保全未发送的手写版本到本地书库，然后清掉该代次的队列、流和游标、回执、临时快照、记录映射、会话凭据及账号绑定。本机书、学习记录、草稿和考卷默认留在仅本地的目录。保留“此目录已退出同步”的本机标记，使下次登录（包括同一 sub 的新代次）也不会自动认领或上传旧数据；重新归属须由用户明确选择。只有用户另行选择删除本机资料才删除本地库。离线设备下次联网确认撤销时执行同一流程。

## 实现验收

1. 用测试服务、账号 X 的 A/B 两个独立数据目录，从真实保存入口创建上表八类数据。A 写、B 拉，再断网同时编辑同一条批注、同一张卡和同一页进度；交换重连顺序，比较两端逐字段结果，包含两份原文、回看前页及同日两次评分。
2. A 删、B 拉。分别重加同页书签、重划同段高亮、重导同一文件再建进度和复习卡，断言原 ID 活跃、新轮次只出现一次。交换未见删除的编辑与删除的到达次序，断言手写草稿有一份恢复副本、纯状态无副本；两轮之间重放旧删除和旧父项的级联删除，新轮保持可见。再覆盖掉回执、提交后退出、90 天后旧设备带未传文字回连。开关关闭时须能离线保存且零网络请求。
3. 在同步功能出现前的 v8 书库和配套考卷库写入八类学习数据，每张映射表至少一行。复制到 A/B 后分别首次升级，设备 ID 和迁移时刻不同。对「仅登录 X、书键全空」和「仅登录 X、书键为空或 X」各跑一轮。两机上送后，用空目录 C 登录 X，逐表比对旧库与 C 的活跃数、墓碑数、稳定键及业务字段摘要，覆盖课程、掌握度、问答出处、FSRS 和未交卷草稿；A/B 重复的旧历史只计一次，同题草稿、错题和卡各有独立 ID。先恢复目录元数据，再从 TON-1894 获取有权限的书。恢复中断重启后继续核对。
   再分别设置第二个已登录身份、唯一非空书键为 Y、书键同时含 X/Y、未解析键、仅设备配对。自动上传均为零，两库仍可读。多账号场景下取消认领仍为零；明确确认后只上传确认范围，Y 的已绑定条目继续归 Y。
4. 测试身份 X/Y 使用同一合成书并故意使用相同记录 ID。对列表、单条、分页、快照、写入、分块及撤销分别断言授权边界和 Y 数据摘要。切换本机账号时注入上一账号的迟到回包。删除 X、尝试恢复旧备份、重放旧写队列、同主体重注册，核 X 学习表及副本归零，Y 内容完整。
   在清理一半时中断并尝试重新注册，预期拒绝；重启清理完毕后重新注册，写入新记录，再投递旧作业，预期新记录仍在。逐项检查删号清单，恢复删号前的混合备份后 X 的旧数据为零，Y 可用。在离线设备上确认本机书、草稿及考卷的条数和内容摘要保持原值，旧代次的队列、映射、绑定为零；再次登录不会自动上传。
5. 设计合入后通知 TON-1891 固定引用格式。实施从最新 main 切，改书库冲突文件前检查对应 2.0.4 PR。测试服务先开；生产切换、迁移与开关由主会话执行。
