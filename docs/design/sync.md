# Windows 学习数据同步与换机恢复

**TON-1892 · 待实现的协议。** 点保存即写入本机，关闭应用或断网不影响这次保存。只有 Hermes 确认持久化以后，这次修改才有异机副本。两台 Windows 设备共用一个 Sable 账号时，各自的离线工作都能进入备份。书的原件、处理结果和书架权限由 TON-1894 提供。产品分工见 [产品决定第 16 条](../PRODUCT_DECISIONS.md)。

## 从哪些数据恢复

盘点基线为 `8cb879c9`。下表的大小是 SQLite 合成样本的增量 KiB。每张代表表单独建在空的内存库中，写 256 行，按写入前后页数差乘 4096 B 计，包含主键索引。使用仓库建表语句，保留列默认值及空值，必填文本用 64 个 ASCII 字符，枚举用短值，整数用行号。没有计外部索引、WAL 和书本文件。真实问答和试卷的长度可变，迁移时另报每表行数和规范化内容字节总和。

## 稳定 ID 与迁移

### 旧库归哪个账号

以同一旧数据目录的 `library.sqlite` 和 `exams.sqlite` 为迁移单位。开启学习同步后，在首次迁移的写锁内取得当前已认证的 Sable 账号 X、该目录所用过的已验证 Sable 身份集合，以及所有书的非空 `books.import_account_key` 去重集合。登录身份按服务器返回的稳定账号键去重；临时 session key 只按已保存的 `book_upload_account_bindings` 映射解析。无法解析的非空键按归属未定处理。卷的 `owner='learner'` 仅用来筛选学习者作答，不能证明归属。

| 已有证据 | 对八类旧数据的动作 |
|---|---|
| 已登录 X，目录仅有 X 一个已验证身份，所有书键为空或解析为 X | 自动把两个库的八类学习数据整体绑定到 X，包括无书键的课程、考点、掌握度、模考卷及学习者作答。即使每本书的键都为空也执行。把绑定和迁移批次持久化，完成校验后用 X 的队列上传。 |
| 登录记录出现第二个账号、任一书键指向其他账号，或有未解析的非空键 | 保持旧库可读，两个库均不入上传队列。展示已知归属和待认领项的分类条数。用户登录目标账号，选中可归其所有的书、课程或独立卷及关联学习数据，确认后才在本地事务记录所选条目和账号。明确属于别人的条目不能改派；含跨账号引用的组保持待处理，取消选择不写绑定。 |
| 尚未登录 Sable 或只有设备配对 | 继续本机读写；在取得 Sable 身份后重新判定。 |

恢复未完成迁移时重用已保存的绑定，重新核验会话和源库书键，出现新冲突就暂停该批次。切换账号先取消旧传输、关闭旧账号目录，再打开新目录；回包校验会话代次。所有权已确定的旧记录不会因再次登录而重新认领。

### 八类数据的记录键

引用为当前账号范围内的 `(kind, recordId)`。下表给出**所有迁移来源**，同时是 TON-1891 的引用契约。每个源表占一行，首项固定为 kind，后续项从左至右取原库列值。书字段使用原文件 SHA-256 小写十六进制；`books.id` 就是这个值。模考卷按旧库的冻结身份 `(book,paper_id)` 引用，导入时校验 `paper_hash`；同键异卷保全两份并报告冲突，再给另一卷分配新 paper_id、重连对应的作答。其他可变内容、排序和设备身份均不参与自然键。

* **编码。** 使用 UUIDv5，命名空间 `8de10572-23e3-43ea-bdb0-b45b39375efa`。名称为无 BOM 的 UTF-8 紧凑 JSON 数组。主键整数用无前导零的十进制字符串。文本保持原大小写和码点；双引号、反斜杠以及退格、制表、换行、换页、回车按 JSON 短转义，其余 U+0000–001F 用小写四位十六进制转义，其他字符原样编码。高亮的 `version` 在 v8 取书散列。例：同一题分别以 `["answer",书,课,模式]`、`["mistake",书,课,模式]` 和 `["card",书,课,模式]` 生成三个 ID。
* **两个旧自增表。** `id` 保留同库内内容相同的多次操作；为区分两个旧库内恰好同号但内容不同的事实，再取不可变事实的摘要。摘要为下列有序数组按上述 JSON 编码后的 SHA-256 小写十六进制。整数同样转为字符串，SQL NULL 写作 JSON null，内嵌 JSON 文本按库存字符串编码。字段全部取自迁移前的行。
  * `turnDigest` 依次取 `thread_id, selection_id, selection_page, selection_start, selection_end, selection_text, section_location, action_kind, label, question_text, answer_text, citations_json, sent_blocks_json, elapsed_ms, created_at`。
  * `historyDigest` 依次取 `lesson, mode, kind, text, revealed, understood, guessed, answered_day`。
  * 相同旧库的两份拷贝即使分别首次升级，也会为同一条事实生成同一个 ID。若两个独立旧库连旧行号和所有事实字段都相同，v8 无来源信息可区分，按一条历史事实恢复，保留两份迁移备份供核对。升级后新增的轮次和作答事件在创建事务中取得 UUIDv4 并持久化；恢复或再导出直接沿用这个 ID。其余行一律按表中自然键派生，新增业务对象的原生 id 在首次保存时固化。
* **迁移与恢复共用映射。** 为每行保存原键、kind 和 recordId。还原到新机时恢复映射，旧自增主键在目标库可重新分配。重传同一基线按账号、kind、recordId 和业务内容去重；设备 ID、迁移时刻和本地自增序列不能制造第二个版本或再次计分。业务内容确有差异才按后文的并发规则合并。

固定样例可供迁移器和导出器交叉验证。书键为连续 64 个小写 `a`、lesson 为 `L1`、mode 为 `CHOICE` 时，`answer` 应得 `e3567cb8-d31b-579c-85f6-495d6f9b3ac1`，`mistake` 应得 `239c9f9f-8edd-5de1-9742-3d4d7cb3dfc9`，`card` 应得 `c2dd5e69-a37a-58d7-bc1f-e2bab35f1ff3`。

### 何时切换

每个源库新增记录映射及操作队列。记录含创建/修改 UTC 毫秒、最后写入设备、因果版本及可空删除时间。原始已知时间照搬，旧行时间缺失用迁移时刻并记 `timeSource=migration`，学习日期仍可为空。保留 `book_notes.revision` 与 `last_mutation_id` 支持编辑器本地乐观锁。旧表、字段、接口本阶段删除清单为空。

停写后先用 SQLite 一致性备份保留两个原库，分别事务建映射、索引、基线队列及完成标记。新写与排队在源库同一事务内完成；两个库均已提交、当前会话仍与绑定相符，才允许发送。崩溃后只重跑未完成的事务。旧已删除批注种下墓碑。比较升级前后逐类主键、条数和业务字段摘要并跑 foreign_key_check、integrity_check；全部通过才切换到新目录。失败继续从旧副本读，保留未上传编辑。

## 写入、重传与拉取

客户端和测试服务显式启用 `COACH_LEARNING_SYNC`，默认关闭。开关关掉期间也可本地编辑；已建基线的库继续记变更，初次启用扫描当前行及已有墓碑。每个源库一个持久写流，服务器从已认证设备绑定取得 deviceId；同设备两库用不同 streamId。每次本地事务取流内递增计数，`opId=(streamId,counter)`；不同窗口共享 SQLite 写锁。一个事务可在一个操作内含多条有依赖的行。网络层复用现有退避、唤醒及单飞机制，学习操作留在业务库，避免写完书库、还没写另一文件的 outbox 就断电。

| 接口（相对路径） | 约定 |
|---|---|
| POST `/learning-sync/push` | 发送协议版本 1、epoch、流、计数、规范化内容摘要、操作数组。每项含 kind、recordId、动作、被修改字段、这些字段已见的版本标识，及时间；删除无正文。客户端按流顺序发送。服务端在一次事务内校验引用、合并、登记回执和账号内递增 seq，持久化后确认。已接收的重复操作不再执行，同 ID 不同摘要报冲突，计数缺口要求从首个缺失值重发。 |
| GET `/learning-sync/changes` | 使用账号、epoch 绑定的不可跨用分页游标；返回有序变更、墓碑、下一游标及高水位。应用远端操作、推进本库游标同事务，不产生二次上传。书库和考卷库分别追到同一水位后才确认设备进度；跨文件引用未到先暂存。 |
| GET `/learning-sync/snapshot` | 新机或游标过期时按固定 seq 枚举一致性快照（含字段版本和流确认位置），各页绑定同一账号、epoch、水位。快照租约过期整次重取。先写临时库，校验计数与摘要并应用其后的增量，成功后切换。期间本地写操作要冻结切换或重放。旧机全量重取前单独保全待发操作及其原始因果上下文。 |

服务端以账号为界串行提交；seq 只用于传输次序。对每个可变字段保留当前未被覆盖的操作 ID。编辑只替换作者实际见过的版本；本机未确认改动作为本地覆盖层，拉取不会覆盖正在编辑的文字。并发标量按 `(Lamport,streamId,counter)` 字典序取最大，Lamport 在观察远端后递增，时钟拨快不会改变胜负。回执丢失重发原字节。限批按编码字节和项数分包；单个大试卷或问答分块暂存，校验整件摘要后同事务发布，过期临时块回收。

书及课程父项先在临时库建最小目录记录，保持原 ID；书的原件未下载时可查看学习记录，原件到齐再按散列重连定位。一次跨页快照未完成时继续保留原活动库。恢复完成同时核对学习快照水位和已授权课程账本的追赶结果。

## 两台电脑同时改一条时

| 数据 | 因果相继的修改 | 独立离线修改 |
|---|---|---|
| 当前页、书签、章节进度 | 跟随新位置，回看前页也能保存 | 页与偏移是一组标量；停留页集合取并集，手动标记优先于推断，两个手动选择按标量规则。书签按 ID 合并 |
| 批注、草稿、高亮 | 编辑覆盖已读版本；删除标记原 ID | 两边在不同字段的修改合并。同一段文字保留每个并发版本，按操作 ID 稳定排序，在读写界面显示，可手动合成一稿并引用全部父版本。高亮按锚点身份去重。删除与未见过的文字修改并发，原 ID 保持删除，另以原 ID 和修改 opId 派生可见的恢复副本；两个到达顺序得到同一副本 |
| 书内问答、错题及作答 | 已完成的 turn 和作答是不可变事实，新提交有新 ID | 取事实 ID 并集，同一操作只计一次。同一题的独立错误都保留，重建当前错题状态；已保存的问题、答案、出处保持配套。同题未提交的文字按批注规则保留 |
| FSRS 与掌握度 | 升级时为每张卡和概念固化状态与已包含的证据边界。新评分记录 rating、学习日、算法版本及参数；新证据使用稳定 event ID | 在共同基线上将新增事实去重，按学习日、因果序号、流与计数重算；原历史已在基线内的只作展示。合并首次独立导入的基线时保留两份原始状态，选有较晚可证复习日期的一份（同日按稳定 ID）为起点，不重复累计旧历史。以领域 FSRS 和 mastery 算法重放，禁止逐列取最大值拼出一张卡 |
| 课程、考点、概念、材料和本地模考 | 逐字段更新，来源/材料按关系 ID 增删；卷内容由冻结 hash 验证 | 显式锁定的编辑优先于自动刷新；并发标题等标量固定择一，手写说明按批注规则。试卷按版本并存，作答按 attempt ID 合并；并发交卷各保留冻结答案及对应成绩。冲突的活动卷选一份恢复计时，另一份作可恢复草稿，避免违反单活动卷索引 |

同一书或课程删除时也记录依赖关系的删除，恢复端按父子关系应用。普通更新不得隐式创建缺失的父项；并发手写内容可保存在账号内独立的恢复条目中，并保留原定位。

## 墓碑、账号和备份

删除在本地业务事务内入队并从正常列表隐藏。服务端记删除操作的因果上下文和 seq，清除已覆盖的正文；并发编辑副本不携带被删版本的正文。墓碑至少保留 **90 天**，且所有活跃设备已确认越过该 seq 后才能清。超过 90 天未确认的设备租约失效。压缩提高最低游标，废止过期流写租约；服务端先检查租约和游标下限，再接收写。旧设备先拉快照，按流已确认计数去掉已收操作，再用新流提交确未收的本地修改，保留原操作身份作为去重键。旧 update 的目标若已消失，只能进入恢复副本；只有有本地创建事实、从未上送的对象才能走 create。快照缺一行不是在别的设备执行删除的指令。压缩回执时保留每流连续计数前缀并拒绝重用旧计数。这样离线半年也不能让已清墓碑的原记录复活。

Hermes 复用经鉴权的 `UnifiedBookScope.fromCall` 推导账号。设备注册、读取单条、变更、快照、分块和回执均先取得同一范围。客户端体内的 owner、书散列、游标、设备号都不能改变范围。关联书籍的恢复可在本账号暂存，下载或读取原件必须再检查本账号书架。共享处理结果不得写入私有学习内容。匿名访问返回 401；外账号 ID 与不存在的 ID 返回同一结果。应用日志仅留类别、条数、失败码。

**每账号一份学习 SQLite 文件及独立备份目录**，路径取服务器解析出的规范范围。新增表为 `sync_meta`（epoch、水位）、`sync_records`（状态、字段版本和墓碑）、`sync_changes`、`sync_receipts`、`sync_streams`、`sync_devices`、`sync_chunks`。同名本地 client meta 不在该文件。学习快照沿用 `LedgerStore.backup` 的 SQLite 一致性复制及完成标记做法；现有 coach.sqlite 的水位不能代表此文件。每个完成副本记账号代次、seq、分表计数及摘要。以校验成功的新副本推进学习备份水位，再裁客户端已确认操作。正常恢复使用最新完整副本，隔离目录校验后换新 epoch，客户端保有的较新操作按原身份补传。回滚到更老副本可能缺中间操作，需先从较新完整副本或保留日志补齐并核对水位，不能将落后状态发布为恢复成功。

**删号顺序**由服务端认证生命周期驱动。先在独立于学习备份恢复的账号注册表冻结该账号代次并吊销会话、设备和写租约，阻止上传与备份工作重新打开文件。等待进行中的事务结束，幂等清除上述七张表所在文件及 WAL/SHM、分块、导出、快照临时目录、该账号的所有完整和不完整备份。共享注册表只留防回滚所需的不可逆代次撤销标记，无学习内容；同一登录主体重新注册分配新代次。恢复任务发布前再次核验代次，旧备份不得恢复已删除账号。删号作业持久记录各步骤完成情况，可在中断后接着做，所有副本清除后才能报完成。书文件、权限和共享引用由 TON-1894 的删号流程同步收尾，其他账号的共享原件照常可用。离线电脑上的旧副本须等下次联网获知撤销才能清理，旧凭据始终不能回传。

## 实现验收

1. 用测试服务、账号 X 的 A/B 两个独立数据目录，从真实保存入口创建上表八类数据。A 写、B 拉，再断网同时编辑同一条批注、同一张卡和同一页进度；交换重连顺序，比较两端逐字段结果，包含两份原文、回看前页及同日两次评分。
2. A 删、B 拉；模拟掉回执、进程在提交后退出、跨库分页中断后重启；以原 opId 重传。推进时钟跨过 90 天，令 B 带未传文字重新上线；分别核对可见条数、墓碑、恢复副本和原 ID。开关关闭时须能离线保存且零网络请求。
