# 从 DeepTutor 真实使用里学到的「小点」→ Coach 要原生满足的验收

来源：2026-10-29 夜对一条真实学习会话（54 轮、34 张题卡）的复盘。DeepTutor 的架构和技术力都够，缺的是这些细节上的闭环；Coach 的价值就在于把它们做成**结构上不会出错**，而不是靠提示词或模型自觉。这份文档只记「现象 → 为什么会这样 → Coach 怎么从结构上避免 → 怎么验收」，不含任何会话原文。

## 0. 一句话
凡是「模型有没有照做」决定的体验，都改成「应用状态机决定」；模型只负责产出内容，不负责流程。

## 1. 答案位置不能靠模型自觉
- **现状锚点（2026-10-29 夜的 origin/main）**：`server/ai/src/main/kotlin/com/coach/ai/Tasks.kt` 第 88、125 行把 `question.options` 当成「字母→文本」的映射交给模型和复核；也就是说**字母现在仍由出题任务决定**。要改成：任务只产出「正确文本 + 干扰项文本」，字母在发题事件里分配。
- **现象**：10-29 20:56 起连续 6 道批量题，正确答案全在 A（模型自己写的顺序里正确答案分别在 C、C、A、C、B、C，存下来却都成了 A）。单题时是散的。DeepTutor 源码里有洗牌，但在生产会话里没起作用，原因没查清。
- **Coach**：题目内容里不带「正确答案是第几个」。出题任务只产出「正确选项文本 + 若干干扰项文本」；字母位置由服务端在**发题事件**里分配，规则：同一组内互不相同，且与最近 N 题的正确位置不同；位置写进 `question_posed` 事件，之后不再变。
- **验收**：领域属性测试（`commonTest`）：任意 1000 道题，每个字母占比在 ±5% 内；任意一组 3 道，正确字母互不相同；连续 3 题不同字母。另加一个「回放」测试：用真实会话语料，确认不会出现整组同一字母。

## 2. 讲解只讲一次，「继续」就是出题
- **现象**：同一批概念（uncertainty vs 信息不对称、逆向选择 vs 道德风险）在一小时内被完整重讲了 6 次以上；用户说「继续」「快点」，导师照样整套重讲，每轮还附一大段固定的「期中怎么考」。
- **原因**：说明书里写死了讲课模板；Week 1 和 Week 4 的知识点内容重叠，导师没有「已经讲过什么」的记忆，只能靠对话历史猜。
- **Coach**：知识点线程里有 `lesson_delivered`（含已讲的**概念 id 集合**）。「继续 / 出题 / 快点」不是对话文本，是状态机转移：已讲过就直接发题。新知识点与已讲概念重叠时，讲解任务的输入里带上「已讲概念」，只让模型讲新增部分，重叠处最多回顾 2–3 句。「考点说明」只在知识点首次讲解时出现，≤3 行。
- **验收**：回放用例：已讲过的知识点上收到「继续」，下一条助手内容必须是题卡，且没有讲解文字；同一概念 id 在一条知识点线程里完整讲解次数 ≤1（回顾不计）。

## 3. 「说了出题」必须有卡片，由应用保证
- **现象**：导师写了「这道题只要心算……选一个就行」，却没有调用出题工具，用户等不到选项，问「你是不是卡住了」，要再催一轮。
- **Coach**：题卡由应用在发题事件里生成，来源是题池或后台出题任务，不取决于模型这一轮有没有调用工具。AI 任务没产出可用题就自动回退到题池，界面永远不显示「说要出题却没有卡片」的状态。
- **验收**：故障注入：让出题任务只返回文字、返回空、返回格式错误，三种情况下界面都能出现一张有效题卡（来自题池）并留下 `fallback_used` 事件。

## 4. 内部文本不进用户可见流
- **现象**：流里出现过「Correction: the above is malformed; the valid call follows.」和 `{"placeholder": true}` 代码块这类内部纠错/占位文本。
- **Coach**：用户可见流只接受带类型的内容块（讲解、题卡、反馈）；工具调用重试、占位、协议文本走另一条通道，不渲染。
- **验收**：黄金测试：在模拟的工具调用失败/重试场景里，渲染结果不含任何协议字样。

## 5. 不强迫「用自己的话说」
- **现象**：某些概念类知识点只有用户写一段自己的话才算通过，用户明确说不想写（边吃饭边学），选择题答对多少遍都不算，导致一个知识点占了 30 多轮。
- **Coach**：已有「两层掌握」（DESIGN §2.2）：选择题连对 3 道（指纹互不相同）即「已通过」，自述/构答只提高「稳固」层，不阻塞。确认此规则在**所有知识点类型**上成立，没有哪类知识点只能靠自述通过。
- **验收**：对每种知识点类型各跑一条「只用选择题」的路径，都能到「已通过」。

## 6. 先讲后考，且讲解不引用字母
- **现象**：导师先出了题、后讲解（用户说「答案应该是 B，但是你前面没给我讲」）；而且导师讲解里写了「答案是 B」，卡片展示时选项已被洗牌，字母对不上。
- **Coach**：发题的前置条件是 `lesson_delivered`；用户直接点「考我」允许，但卡片上标注「这点还没讲过」。导师文本里不引用选项字母，只引用内容；反馈文本在判分时用最终字母生成。
- **验收**：任意题卡的反馈里出现的字母必须与卡片一致（自动比对）。

## 7. 一次多题，默认三道
- **现象**：用户明确要求「一次出多道，不想一次只做一道」。
- **Coach**：默认 3 道一组，每题独立判分，一次提交；离线也能做（DESIGN §1.4）。

## 8. 「答所问」由应用先答
- **现象**：问「学了百分之多少」时，导师答非所问、跑回当前知识点。
- **Coach**：进度、剩余、分值覆盖这类问题由应用从投影直接回答（不经模型）；模型只负责解释。
- **验收**：对「进度/还差多少/复习安排」类问法，首条回答来自投影，且数字与今天页一致。

## 9. 怎么防止再漏小点
每次真实使用后，把这类问题变成**回放用例**放进测试（语料只放本机，不入库，公开仓库只放脱敏后的结构化断言）。M1 验收增加一条：用最近一周的真实会话回放，上面 1–8 条的断言全部通过。
