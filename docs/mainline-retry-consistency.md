# 选择题主线：键变化与重试一致性（TON-1364）

题键的有效性变化沿用 `DESIGN.md` §2.2：在 `question_key_changed` 事件处生效，不回写成学生在历史作答日已知道题键有问题。因此，d0 用 VERIFIED 键答对，d20 降为 UNREVIEWED / REJECTED，新增的「再看一次」从 d21 开始。已存在的更早到期日取最小值：原定 d14 仍是 d14，原定 d40 提前为 d21；未通过的知识点同样从 d21 再看。重放事件顺序不会产生 d1 的虚构截止日。

这只修正新增再次查看的时间基准，不把键变化当成一次新的复习作答，不增加 FAIL / PASS 统计，不推后已经到期的复习。三次有效首答、有效性撤销、迁移锁存和未核键不判错的定义保持原样。

一个 submissionId 绑定已入账的周、itemId 和题目指纹。相同题目重试返回原 choice、guessed 和选项排列；题目身份错配返回 HTTP 409，不追加事件。客户端最终选中态和对错标记使用响应的 choice，掌握与猜测结果继续使用服务端状态，即使重试前用户已经改选或切换「我是猜的」。

验证使用合成果园夹具：领域测试覆盖 d20 降键及已有到期日；真实 HTTP 测试覆盖旧排列 / shuffled-v1、跨题冲突和关闭重开账本；Compose 测试覆盖丢包后错答、猜对、确定答对的改选重试。模拟器在现有主线走查中用 `--retry-after-commit` 代理丢弃三次首次成功回包，再核对 UI 选中态、guessed、响应和账本一致。它验证合成流程，不代表真机或生产验收。

测试代理只转发 HTTP，不转发 WebSocket；走查截图中的「Mac 未连接」横幅来自这个夹具限制。本次模拟器走查不验证实时连接与重连。
