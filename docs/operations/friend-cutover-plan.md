## 配置变更与数据边界

私有 staging 中逐项比较配置，允许的变化只有已审查的 release 路径替换，以及新增 `COACH_PUBLIC_PORT`、`COACH_FRIEND_CONFIG`。保留 owner 正常端口、原数据目录、配对凭据、资料目录和服务管理设置；**本次不迁移 API state 根目录**。

| 变量 | 要求 |
| --- | --- |
| `COACH_PUBLIC_PORT` | 选一个当时未占用的有效端口 P；排除 18791、正常端口、bridge、mathsvc 和任何现有监听；切换前再次检查，冲突就停止，不关占用者 |
| `COACH_API_STATE_DIR` | 保持原设置及解析后的实际目录不变；原来未设置就继续未设置，并固定原服务 HOME，使用既有 `Coach/state`。不得指向新空目录；JVM 与 bridge 的解析结果须相同 |
| `COACH_FRIEND_CONFIG` | 受限的绝对私有配置路径；JVM 与 bridge 一致，显式额度及全局 `paused: true` 起步，不依赖缺省额度 |

`Main.kt` 的朋友端口仅绑定回环，且拒绝 18791 和正常监听端口；朋友端口绑定失败会使启动失败，须走回滚。`ChildServices.kt` 的子进程继承环境，因此不能只给 JVM 或只给 bridge 设置上述路径。已有 API 凭据继续由 bridge 的 Keychain 路径读取，不放入 plist、代码、评论或 Actions。

`tools/bridge/api_budget.py` 在同一 `api-credit-ledger.json` 保存 owner 的 `cycles`、`months` 和朋友的 `friends`；朋友预留也占 owner 月预算。朋友隔离依靠 `friends[id]` 与 `state/friends/<id>/`，不另起预算根。在受控停止、持锁且无在途写入的检查点，私下记录实际 state 目录身份，以及 `cycles` 的 spent/limit/reserved、`months` 和朋友明细；启动后首个请求前核对连续性，随后按实际调用核对费用与预留增量。保留 `api-spend-*.json` 汇总和未知预留，切换与回滚均沿用同一账本，不重置、不回拷旧文件。目录身份或连续性不符即停止。未来若确需迁移，须另审受控完整复制和一致性证明，不属于本方案。

配置中的朋友名、设备 ID、实际地址及配对回包只存私有记录。先完成原 owner 的五分钟验收，再签朋友配对码，避免改写单例配对码影响原有验收。解除暂停也必须有明确测试额度；暂停不能撤销 token、停止在途请求或代替关闭入口。

## 旧版回滚的凭据风险

实际旧版 `eb2d87a7` 的 `LedgerStore.authorize` 只检查 `devices` 中未撤销的设备及 token 哈希，没有朋友身份区分。候选在同表新增 `friend_name`。因此，**仅停止 Funnel 并回退旧代码，会使仍有效的朋友 token 被旧正常监听接受，进入设备级数据路径（课程、账本、复习、阅读）**；不含仍要求 `X-Coach-Device == desktop` 的专属管理路由。这是源码推导，尚未在实际旧/新安装的隔离回滚中验证；不能以“表只新增列”认定回滚安全。

任何回到这个旧版的路径，包括启动失败、五分钟验收失败和后续主动回退，必须先满足以下顺序：

1. 关闭本次新增的准确 Funnel 规则，保留其他人的配置。禁止 `funnel reset`。停止朋友入口和候选的目标进程，确认其受管子进程已停止并取得独占操作锁。关闭 Funnel 失败时也不得继续暴露朋友入口；保留停机状态并报告，不能宣称撤销成功。
2. 新服务仍可用时，可先经管理员接口吊销全部朋友。**仍须有独立的离线路径**：`app revoke-friend` 依赖运行中的 HTTP 服务，不能覆盖候选崩溃或绑定失败。
3. 离线工具在确认唯一数据目录、数据库身份和新增列存在后，以同一 SQLite 事务把所有 `friend_name IS NOT NULL AND revoked_at IS NULL` 的设备置为已撤销，并使尚未消费的朋友配对码失效。保留已有撤销时间、owner 行和 owner 待用码。提交并重新核对活跃朋友为 0、待用朋友码为 0、owner 凭据不变；输出仅计数，不输出身份或哈希。原本已经停用的朋友也不可复活。
4. 只有在朋友隔离已持久化、旧版本读取迁移后数据库的兼容演练通过后，才恢复旧 release、plist 和安装记录并启动旧服务。没有证据就保持停止，不绕过隔离检查启动旧版。
5. 保留切换后的用户写入、导入、撤销、费用、预留及结算记录。常规回滚只恢复代码和配置，**不恢复切换前数据库快照、不清零预算**。一致性备份用于灾难恢复，不能覆盖刚完成的吊销。若必须恢复数据，另立经审查的恢复流程，旧服务仍保持停止。

还要拦截“直接执行旧 stage 的 rollback”这种旁路；不能让未经隔离的旧版本通过另一个入口启动。离线隔离失败、数据库身份不符、锁取不到、残留在途写入或旧版本兼容失败，均为停止条件。

上述离线隔离工具和旁路保护**尚未实现**。本轮不修改 TON-1663 执行器；这是生产前必须补齐的工程项，不能用本文代替实现或验收。

## 执行器适配与隔离演练

首版观察到的 TON-1663 私有执行器固定了另一源码候选，预检只接受原 plist 的 release 路径替换。增加朋友端口和配置变量会被拒绝；其回滚保留数据库，但没有朋友凭据隔离。`tools/dev/ton1175_switch.py` 的 staging 也不会自动增加这些变量，`ton1175_launchd.py` 只用于测试标签。不可直接复用旧审批、放宽检查或运行通用 install 来绕开它们。

租约释放后，由下一刀提交有界的执行器差异：只允许新增端口和朋友配置两项，API state 设置、服务 HOME、解析目录及其他项保持不变，检查 P 的独立回环监听，绑定实际候选及全量哈希，加入离线隔离与所有旧版启动路径的保护，保存原配置并保留数据库新写入。先提交 reviewer 和另一个合格 `cross_review` 验收者；两者必须与执行者异厂，且彼此不是同一人、不是同一模型。本文普通审查通过不等于生产交叉审批。

## 有序执行与失败处理

以下是未来实际执行顺序，本轮均未执行。实际命令和受限路径由冻结后的 stage 记录给审查者，命令行不得含地址、token 或配对码。本文不提供当前尚不成立的 `--apply` 命令。

1. **冻结**：确认窗口与文件租约释放、最终 main 冒烟完成，重新采集安装指针、plist、Funnel 配置及数据身份；从最新 main 选择包含 #371/#373 的确切候选，制作并验证不可变安装产物及依赖。使用 `ton1175_verify.py` 的产物证明流程，不能只读取 `source-head.txt`。原生窗口释放后才派发 `friend-windows.yml` 的 package 阶段；记录 run ID、head SHA 和包哈希，probe 必须引用该成功 package run。工作流核对 run 的 head/event/path/conclusion，再核对包内 `commit.txt == GITHUB_SHA`；main 已移动就重新构建并审查，不能混用旧包。
2. **非生产门禁**：上述矩阵和实际候选自查通过，备份及兼容恢复演练通过。首次公网暴露也须先审批：独立 HOME、无生产数据/凭据、有限额度的候选监听先过本地门禁，经审查才临时以唯一 Funnel 规则指向该朋友回环端口，运行下述协议和原生 package/probe 检查；结束关精确规则、吊销全部测试身份并核对状态。不得占用他人的 serve/Funnel 配置，不复用生产朋友码。临时入口不指向 18791，失败保持关闭，不进入生产切换。临时外网权限或窗口未就绪就保留此门禁未通过，不为赶进度先暴露生产。取得外网结果后，生产 reviewer、独立 cross_review 对冻结候选、执行器和回滚计划明确批准；准备原配对设备和获准真实资料，有缺项就不申请生产窗口。
3. **真实空闲**：以 `tools/dev/activity-coverage.md` 要求取得连续 900 秒完整活动证据，绑定同一进程、启动时间和安装身份；存在活动 WebSocket、用户请求、观察缺口或证据过期即重取。健康检查、进程空闲和“日志没看到请求”都不替代此门禁；证明封口后直到受控停止都保持保护。
4. **受控切换**：在保护下做一致性备份和写入水位核对；停止准确目标实例，原子更新已批准的 plist/安装记录，启动候选。Funnel 此时仍关闭，配置仍暂停朋友计费。从受控启动开始计五分钟，在已准备好的原生设备检查原 owner 配对、真实讲课和做题、账本及身份。失败或超时立即进入前述隔离后回滚；不能把重试或重签身份当成功。
5. **开放**：owner 验收通过后复核没有其他 serve/Funnel 配置，再按 [Funnel 命令及撤销](friend-public.md#funnel-命令及撤销) 开唯一 HTTPS 443 → `127.0.0.1:P`。核对唯一目标为朋友端口，**Funnel 永不指向 18791**。配置漂移、非预期监听或任何私有路径泄漏，立刻关本次入口并暂停后续测试；如需回退旧代码，必须先执行朋友隔离。
6. **生产外网复验与收尾**：入口开放后，对同一冻结候选重新运行下面两类手动工作流，不能用临时实例的成功代替生产结果。真实朋友资料/API、额度与撤销在获准私有原生环境另验；本轮不新增 GUI 队列、不做安装包、不改 tonii。本机管理侧无论成功失败都吊销全部测试朋友，确认 401、清理临时秘密，保留费用与撤销记录。

两类外网工作流各自留 head、run 链接、实际命令与退出码；仅在对应窗口及门禁获准后派发：

| 工作流 | 秘密、资料及证据边界 |
| --- | --- |
| `friend-public.yml`：surface/revocation | 受保护 environment 的步骤 env 注入 `COACH_FRIEND_*` 及 A/B 临时凭据，配对回包另遮蔽字段；禁 shell trace，无 artifact；只证明协议与撤销，不发计费讲解 |
| `friend-windows.yml`：package → probe（`package_run`） | probe 同样限定 main、受保护 environment；步骤 env 注入 `COACH_EXTERNAL_URL`、`COACH_EXTERNAL_CODE_A/B`，不写入 PowerShell 源码或参数。只用驱动自写材料；配对块消失后才截图。artifact 仅限现有自写材料证据白名单、包和提交记录，不能加入真实教材、地址、身份、凭据或原始日志。Mac 操作者须提前就位，在 Revoke 最多 180 秒内撤销 A 并验证 B 可用；超时是失败，不能当已撤销 |
