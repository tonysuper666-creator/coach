# Android application updates

The paired Android app checks `GET /v1/app-update?packageName=<installed package>` on launch and foreground. No release returns 204; an unavailable server leaves learning usable. A newer release offers download with progress, verifies SHA-256, exact package/version and the installed signing identity, then opens the Android installer. First use opens Android's per-app permission screen and continues after permission is granted. Cancelling installation leaves an install button. The app never uninstalls or clears its database or Keystore pairing.

Both endpoints require the normal device and bearer headers. `GET /app.apk?sha256=<digest>` reads an immutable content-addressed file, so publishing while another device downloads cannot switch its APK. Redirects are refused by the downloader. APKs are bounded to 256 MiB; a failed or interrupted download can be retried. Signing rotation is deliberately refused; keep the existing debug keystore (DESIGN §10).

Installation uses an explicit activity selected from enabled, exported system APK handlers with the privileged `INSTALL_PACKAGES` permission. Third-party defaults and choosers never receive the APK URI grant. If no trusted system installer is available, installation stops with an error instead of falling back to an implicit intent. The manifest exposes only the APK-handler query needed for Android package visibility.

Build via `tools/dev/heavy ./gradlew :androidApp:assembleDebug`. The code is automatically reserved using a locked private counter in `~/Coach/builds/version-code`, shared across worktrees. `-PcoachVersionCode=N -PcoachVersionName=NAME` is available for reproducible isolated acceptance builds; published codes must increase. Debug and release use the existing debug signing identity. The existing application ID remains unchanged.

Publish with `python3 tools/dev/publish-app.py androidApp/build/outputs/apk/debug/androidApp-debug.apk`. The publisher verifies the APK's signatures and extracts its actual package/version with Android SDK tools, refuses a changed signing identity or non-increasing code, writes an immutable APK, and atomically replaces the package's `latest.json`. Default private directory: `~/Coach/builds/updates`; override with `--directory` and the server's `COACH_APP_UPDATE_DIR`. For acceptance use an isolated directory, port and package (`-PcoachApplicationId=com.coach.android.ton1252 -Pcoach.port=<test port>`); never publish acceptance APKs to the production update directory.

Before invoking any SDK tool, publication makes a bounded copy of the build output into a private directory (0700), closes the writer and makes the snapshot read-only (0400). Signature, package/version, size and digest checks all read that snapshot; publication atomically moves the same snapshot into its content-addressed destination. Replacing the original build output during verification cannot alter the release. The synthetic fake-SDK regression needs no heavy lock: `python3 tools/dev/test_publish_app.py`. To demonstrate the old race, set `COACH_PUBLISHER_UNDER_TEST` to a saved older publisher and run `python3 tools/dev/test_publish_app.py PublishAppTest.test_source_replacement_during_sdk_checks_cannot_change_release`: a vulnerable publisher exits successfully but fails the consistency assertions for replacements after either SDK check.

Run server checks with `tools/dev/heavy ./gradlew :server:app:test --tests com.coach.server.AppUpdatesTest`. Android `AppUpdateSmoke` takes locally built N+1 APK fixtures (`valid`, `wrong-signer`, each APK plus JSON metadata) in the target package's private `files/update-fixtures` directory. The harness streams them through `adb shell -T run-as <package> tee <file>` so they are created by the debuggable app's UID; disabling the PTY preserves binary APK bytes and the shell protocol reports remote write failures. Shell-created external files can be unreadable on API 35. Run its verifier and seed methods on N, update via the actual UI, then run the retention method on N+1. Keep screenshots, pre/post `dumpsys package` and command results in private acceptance evidence. Production rollout remains a separate reviewed deployment; old installed builds without this updater need one bootstrap installation.

For a complete foreground emulator run, use `tools/dev/heavy --emulator python3 tools/dev/check-app-updates.py --prepare --artifacts "$HOME/Coach/state/ton1252"` with JDK 17 on PATH. The `--emulator` flag reserves the single emulator lane, including this session's fixture builds; commands without it use the separate build lanes. This builds the isolated N/N+1 package and a temporary synthetic signing identity, takes a read-only SQLite production backup, disables real tutor calls, boots its own emulator, checks both refusal screens, installs through Android's UI and compares every existing local learning event plus the Keystore pairing. It shuts down its emulator and server before returning. The private evidence directory contains screenshots, version dumps and content-free test results; never commit it. Phone acceptance is separate and requires `~/Coach/testphone/wait.sh` registration and a granted lease after this emulator gate passes.

When production reads are outside the task's scope, pass `--database-copy /path/to/authorized-copy.sqlite` (a synthetic ledger is also supported). The source is opened read-only and backed up into the isolated artifacts directory. Generated coursework and mock-paper directories are always confined to that directory; this harness never needs the private materials tree. Keep the same refusal and retention assertions when using synthetic events.
